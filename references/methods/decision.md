# 方法卡：决策与行动

> 按需加载。适用于把机制解释变成有执行者、有验证、有护栏的行动，以及判断干预是否可行。

## 问题

谁能做这件事？第一步是什么？做完怎么知道有没有用？什么情况下应当停手或改做别的？

## 假设

- **"建议正确"不等于执行者有权限、预算或验证条件。**
- 系统生存不等于所有主体受益。局部改善可能只是把成本转移给了没被纳入边界的人。
- 结构中心性高 ≠ 可干预。图里连得多只说明波及面大。

## 观测：干预可行性审查

在把某个机制推为干预目标之前，逐条回答：

| 审查项 | 问什么 |
|---|---|
| 权限 | 谁有权做这个改变？用户是这个人吗，还是只能影响这个人？ |
| 提前量 | 从决定到产生可观测效果需要多久？反馈延迟多长？ |
| 不可逆投入 | 一旦启动，哪些成本收不回来？ |
| 成本区间 | 钱、人、时间的量级，不是"投入资源" |
| 阻力 | 谁会反对，为什么——他们的利益是什么 |
| 受损方 | 谁承担代价？包括没有发言权的主体 |

## 推论：行动卡字段

| 字段 | 必须回答 |
|---|---|
| 行动与机制 | 具体改变什么，通过哪个机制（`mechanism_id`）改善哪项结果 |
| 适用角色与权限 | 用户能直接做 / 能推动别人做 / 只能监测 |
| 最小下一步 | 第一个可交付动作、前置条件与**完成定义** |
| 资源与提前量 | 成本范围、人员、时间、依赖、不可逆投入 |
| 替代项 | 维持现状 / 先补证 / 先试验 / 直接干预的取舍 |
| 收益与受损方 | 各主体的收益、成本、风险转移与阻力 |
| 验证设计 | 基线、结果指标、对照或比较方法、观测窗口 |
| 护栏与退出 | 副作用指标、停止条件、回滚或切换办法 |
| 决策触发 | 什么新证据使它启动、延期、升级或取消 |

**对外部观察者**（无干预权限）：输出"该关注什么、需要争取何种权限、哪些证据值得补查"。
不默认读者能改变组织薪酬、制度或国际关系。

## 反证：验证设计的两个陷阱

1. **指标迎合**——用行动本身瞄准的指标验证行动。上报数上升可能是渠道生效，也可能是口径变了。
   尽量用**独立结果指标**、抽样审计与干预后的替代行为观察。
2. **风险转移**——局部改善来自把成本推给别处。验证时把被排除的成本与主体重新纳入再看一遍。

试点期间：不能只以"上报增加"判定恶化，也不能只以"投诉下降"认定因果效果。

## 行动：用小型验证替代大而确定的处方

主要机制尚未区分时，优先提出能**低成本区分机制**的试验或数据核查。
不能试验时，提出过程追踪、匹配案例或自然变化观察，并说明混杂限制。

**不要求每条解释都产生立即干预。** 有时最实用的结论是：

- 现在不具备行动依据，需要先补齐某条决定性事实；
- 继续保持某个缓冲，不动它；
- 提前保留退出选项，为将来的切换留提前量。

## 适用限制

- 行动卡不构成对具体组织、法律或财务事项的专业建议。
- 溢出与冲突的传播数值是**序数启发式**（无单位、无延迟、无阈值），
  只能用于比较方向与波及范围，不得据此承诺改善幅度。
- 高风险未决断言可以让依赖它的行动**不可推荐**（`blocked_by_claims`），
  但不应导致全部研究成果无法保存。
