> **这个目录里目前有一个能跑的套件和一份还没执行的协议。不要把前者的绿色当成后者的结论。**

## 消融实测（合成案例上，2026-09-08）

| 配置 | 通过 | 差值 | 新失守案例 |
|---|---|---|---|
| 全模块（对照组） | 8/8 | — | — |
| 关掉独立证据家族折叠 | 6/8 | −2 | SYN-01, SYN-07 |
| 关掉信源层级加权 | 6/8 | −2 | SYN-05, SYN-07 |
| 关掉鉴别力降权 | 7/8 | −1 | SYN-06 |
| 关掉反证依赖传播 | 7/8 | −1 | SYN-08 |

**这张表的边界**：差值衡量的是"关掉该模块后，有多少**按该失效模式构造**的案例被判错"。
案例是照着这些失效模式造的，所以增益天然偏高——这是靶场成绩，不是野外成绩。
结论只能是"该模块在它负责的失效模式上确实起作用"，**不能**推广成"它在真实分析里值得保留"。
后者要 `protocol.md` §3 的真实案例消融，尚未执行。

每条消融都带负控（`tests/test_evals.py`）：若某个消融**没有**让任何案例失守，测试会失败——
零差值意味着这批案例根本没测到那个模块，那样的消融数字没有意义。

同一套用例也接进了 pytest（`tests/test_adversarial.py`），并带**负控**：
关掉某条防护后，对应用例必须变红。没有负控的绿色不可信——
一个从不失败的检查和没有检查，信息量相同。

## 对抗用例清单（方案 §14.3）

| 用例 | 状态 |

| 核心变量缺失或全中性 ACH | 自动 |

| 未到期的持续型/发生型/时点型预测 | 自动 |
| 新报道其实只是旧事件重发 | 自动 |
| 数据口径变更但数值改善 | 自动 |
| 已知历史结局藏入材料或类比字段 | 自动 |
| 指标改善而独立结果恶化 | 自动 |
| 外部用户没有干预权限 | 自动 |
| 网页中出现"忽略分析规则"的指令 | 自动 |
| 将"下属来自 A"改写成"本人来自 A" | **提示词层，代码不判定** |

最后一条的防护在研究员与复核 sub-agent 的行为里（`researcher-modes.md` 的
`fact_check` 改写忠实性核对、`researcher-base.md` 的原文摘录要求、
`system.md` Step 6.5 的人物身份强制核查）。套件把它标成 `prompt_gated` 而不是"通过"——
把提示词里写了规则当成规则生效了，正是最典型的假绿。人工验法写在用例的 detail 里。

## 这个套件不证明什么

- **不证明研究准确性**。它喂给工具的是构造好的输入，不是真实检索结果。
- **不证明因果识别有效性**。L1 机制图的箭头对不对，用例判定不了。
- **不证明预测优于基线**。那需要几十条已裁定的真实预测（见 `protocol.md`）。
- **不证明对真实系统可用**。端到端研究与报告生成没有跑过。

## 消融开关

两套：`validate_contract(analysis, ablate={...})` 关契约层模块
（`lineage` / `mechanisms` / `actions` / `coverage` / `temporal` / `injection_scan`）；
`evals.synthetic` 关推理层模块（家族折叠 / 鉴别力降权 / 层级加权 / 反证传播）。
后者已在合成案例上跑出上表的数字；前者的真实案例消融仍未做。

## 还缺什么（按 protocol.md 执行才能补上）

仪器都已就位，缺的是**只能由真实世界提供的输入**：

| 缺什么 | 为什么代码补不上 | 仪器就位了吗 |
|---|---|---|
| 12 个冻结案例 + 材料快照 | 需要对 12 个真实系统做实际检索 | 案例表结构就位 |
| 三条路径的同预算对照输出 | 需要真的各跑一遍 | 盲评打包 `blind_package()` 就位 |
| 两名独立评审的逐案打分 | 需要人 | 判据执行 `score_case()` + 汇总 `aggregate()` 就位 |
| ≥30 条已裁定的前瞻预测 | 需要时间流逝 | 冻结与裁定 `forecast_registry` 就位 |

在这些做完之前，本项目对现实分析准确率、预测优势或部署可用性**没有验收结论**。
合成案例的 8/8 与对抗用例的 11/11 **不是**这个结论的替代品——
它们证明的是逻辑正确，不是判断有用。
