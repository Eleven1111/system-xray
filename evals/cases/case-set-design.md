## 抽样设计

方案 §14.1 要求：企业／机构、平台／市场、关系系统各 4 个，每组覆盖
**稳定 / 恶化 / 恢复 / 证据稀疏** 四种状态。三条约束值得说清为什么：

1. **四种状态，不是四种难度。** 状态标签是**抽样分层**，不是被检验的真相——
   评估测的是决策增量，不是"能不能把系统分类对"。选案时按当前公开认知归类即可；
   若后续发现归类错了，如实记录，**不换案例**（换案例就是在挑对自己有利的样本）。
2. **避开"全是著名失败"。** 只测崩溃案例，测出来的是"能不能识别已知灾难"，
   那个能力训练知识就有，不需要这套协议。所以每组必须有稳定与恢复态。
3. **著名度是污染代理指标。** 越有名的案例，模型训练知识越可能直接给出答案，
   三条路径的差异会被压缩。因此在同等条件下**优先选中等知名度**的对象，
   并接受这只是减少泄漏、不能证明消除（§14.1 已声明）。

## 每个案例要冻结什么

| 项 | 说明 |
|---|---|
| 材料快照 | 固定材料轮用的全部原文，存 `evals/cases/materials/{case_id}/` |
| 信息截止点 | 快照采集的时刻，之后发生的事一律不得进入分析 |
| 事件定义 | 若该案例要出预测，事件语义与裁定窗口须此时定好 |
| 参考判据 | 这个案例上"什么算合格新增洞察"的领域特定说明 |
| 三条路径的预算 | 工具调用次数 / 耗时 / token 上限，三条必须可比 |
