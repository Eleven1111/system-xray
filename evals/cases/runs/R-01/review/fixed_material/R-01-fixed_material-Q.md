# Rust-for-Linux 与内核维护者的互动格局

**as_of 2026-09-09。判断仅依据同日采集的材料快照，未覆盖的事实一律标为未知。**

## 一、系统是什么

这个关系系统的两端不是"Rust 阵营"和"C 阵营"两个均质集团，而是四个位置：
(a) R4L 的推动者（Ojeda 及贡献代码的驱动开发者），
(b) 顶层裁决者（Torvalds），
(c) 愿意主动吸收 Rust 的子系统维护者（Airlie/DRM、Kroah-Hartman 的表述所代表的那一类），
(d) 被 binding 波及但自身不写 Rust 的核心子系统维护者（Hellwig 的 DMA 是范例）。

真正的张力不在 (a)–(d) 之间，而在 (b) 对 (d) 施加的耦合条款上。R4L 自己没有权力强制任何人，
它的全部推进力来自 Torvalds 那条规则：没有人被强迫用 Rust，
但**选择不参与的维护者同时放弃对影响其子系统的 binding 与集成如何开发的影响力**（M2）。

## 二、核心机制：一条被误读为中立的条款

这条规则表面是自愿原则，实质是**单向棘轮**：它把"不参与"从零成本改造成有代价——
弃权者失去的不是写 Rust 的机会，而是对自己领域内一段代码的否决权。
在维护者的核心资产就是子系统裁量权的社群里，这个代价定价极高。
它不产生"强迫"，只产生**单方向的持续漂移**：每次弃权都让下次弃权更难。

Hellwig 的反应正是对这个机制而非对 Rust 语言的反应。他的三条指控指向三个不同层面，
应当分开看：

1. **程序层**：一份网页不构成政策，要生效必须进入内核树并获得广泛同意（M1）。
   这是关于"政策存放在哪里、由谁同意"的争议，与语言无关。
2. **诚信层**：文档称"没有子系统被强迫"，而 Torvalds 的私下立场与之冲突；
   他还指 Linus 公开躲在"实验"这个说法后面（M1）。指控的对象是**公开表述与实际裁决之间的落差**。
3. **技术—结构层**：binding creep——最终每个非叶子子系统都会被波及；
   他用"癌性肿瘤"形容 wrapper 的扩散（M1）。

(3) 最易被当作情绪化修辞驳回，但它在拓扑上成立（见第四节）；
(1) 和 (2) 才是更难修复的部分——一旦被公开提出而未被正面处理，
损伤的是裁决程序的可信度，而非某个技术决定。材料未显示这两条得到过回应。

## 三、载荷点：一次归类分歧

M2 记录的分歧是整个系统的承重结构：Hellwig 认为 DMA 被迫接受 Rust；
Linus 与 R4L 认为 DMA 的 Rust binding 只是 DMA 的**又一个使用者**，不属于 DMA 子系统本身。

同一份代码，两种归类，而归类决定的是**谁承担维护成本、谁拥有否决权**。
若 binding 属于子系统，它进入维护者的负担与裁量范围；
若它只是下游使用者，维护者既不必管它，也不能拦它——但接口一旦被使用，
后续的每次改动就都要考虑它是否会破坏这个使用者。

因此"binding 只是使用者"并不消解 Hellwig 的担忧，只是把成本从"维护责任"
重命名为"兼容性约束"。材料中没有任何一方处理这个转换——这是最未解决、也最易复发的一点。

## 四、"子系统自治"为何不能稳定这个系统

官方政策反复强调子系统自治：如何处理 Rust 由各子系统自行决定（M4）。
但自治在内核的依赖图上不是均匀分布的：

- **叶子位置（驱动）**：自治是实的。新驱动是绿地，作者自选语言，没有既有维护者被牵动。
  材料中 Rust 代码的落点几乎全在这里——Apple silicon 驱动、Google 的 Android 专用驱动、
  开发中的 Nova（NVIDIA GPU）、NVMe 贡献、GPIO 抽象，加上 `rust/` 的核心基础设施（M4）。
- **非叶子位置（核心子系统）**：自治是形式的。它的采纳与否由**下游**决定——
  只要有一个 Rust 驱动需要 DMA，DMA 就需要 binding。
  这正是 binding creep 的机制，而它是拓扑的必然，不是谁的意图。

"自治"一词在两个位置上含义不同，政策文件用一个词覆盖了两种处境。
它没有消除冲突，只把冲突从全局下沉到每个非叶子子系统的边界上逐个重演。

第二个不对称：自治是**双向**的。Airlie 说 DRM 大约再有一年就要求新驱动用 Rust、
不再接受 C（M4）——自治条款第一次被用在推进方向上。同一条规则既允许拒绝也允许强制，
故它不是防守性保障，谁掌握子系统谁就能定向使用它。（材料只有这一处表态，且是预告。）

## 五、"实验结束"改变了什么

2025-12 的补丁 "rust: conclude the Rust experiment"，与 2025 年东京 Maintainers Summit
认定实验结束（M3），其关系意义大于技术意义：**它取消了退出选项**。

"实验"这个标签给反对者提供了一个可讲述的未来——实验可以失败、可以终止。
取消它之后，举证责任翻转：此前 R4L 需要论证自己值得留下，此后弃权者需要论证
自己为何不参与。Hellwig 抱怨 Linus"躲在实验后面"，恰恰说明这个标签在争议期
一直被两边当作缓冲；缓冲移除后，第三节那个未解决的归类分歧不再有推迟处理的余地。

同时被固定的还有**永久双语状态**：Rust 是增补而非替代，乐观估计到 2030 年
不到内核代码的 5%，现实是数十年共存；Ojeda 也告诫这不代表在每种配置、架构或
工具链下都能工作（M3）。所以这不是一次转型阵痛而是**长期常态**——跨语言维护成本、
双语审阅要求、非叶子子系统上的归属争议，都会以低强度持续存在，不随某个里程碑消失。

## 六、材料的限度与不能下的结论

- **M6 的否定性发现**：材料未找到 2026 年 Maintainers Summit 的结果，
  永久化决定来自 **2025** 年峰会；也未找到 2026 年内新一轮公开冲突的报道。
  "无报道"有两种读法——冲突已被吸收，或只是本次检索未覆盖。
  这两者用现有材料**无法区分**，不能据此宣称关系已经缓和。
- **未知项（材料无数据，不以背景知识补）**：Hellwig 或 DMA 一侧此后的立场是否变化；
  是否有维护者因此退出；binding 的长期维护劳动由谁承担、是否有新人力到位——
  而第三节表明整个争议的实质就悬在这最后一项上，材料恰好没有它。
  DRM 的"再有一年"是否兑现，同样未知。
- **可靠性降级**：M5 中"Linux 7.0 于 2026-04-12 发布并移除 experimental 标签、
  Rust NVMe 与高速网络驱动进入主线稳定树"，检索工具自行标注了警告称其来自二手博客
  而非内核源，本分析**不采用**。Debian APT 的 hard Rust requirements、
  Android 16 的 Rust 内存分配器、Ubuntu 25.10 默认 Rust coreutils 同为二手来源，
  且属于发行版/用户态，与内核内部的关系格局只有间接关联。

## 七、判断

这个系统在 2025 年底完成的是**性质变更而非争议解决**：取消"实验"标签，
把一个可逆的、以说服为主的关系转成不可逆的、以位置为主的关系。
推进力不来自技术优势论证（Kroah-Hartman 关于 Rust 驱动更安全、Rust/C 交互问题
少于预期的表述属于此类，材料未见对应量化证据），而来自那条把弃权与失权绑定的规则。

因此可预期的不是崩解也不是和解，而是**争议的分片化**：每个非叶子子系统在自己的
边界上把"binding 属于谁"重演一次。稳定性变量不是采纳率，而是 binding 维护劳动的
到位程度——推动方持续供给人力，归类分歧就停在措辞层面；不供给，成本静默落到被波及的
维护者身上，程序层与诚信层的旧账会被重新提起。材料未提供判断这一项的任何数据。
