## 1. 决策摘要：最重要的判断是"证据不足以区分缓和与下沉"，而不是"关系已经缓和"

**最重要的判断（一句话）：** 政策层面的冲突（"要不要在内核里用 Rust"）在 2025 年底被一次可追溯的裁决关闭了，但引发 2025 年争议的那个真正分歧——**Rust binding 在归类上属于谁的子系统、谁承担它的维护负担**——在材料里从未被解决，只是失去了公开载体；现有证据**不能区分**"关系真的缓和了"和"冲突下沉到子系统层、公开度下降"这两种解释。

**建议动作及执行者：** 执行者只有读者本人（外部观察者，只能监测）。核心动作是把监测对象**从"是否还有 Rust 争议"改为"是否出现新的归属/负担争议"**，并把 M5 中带警告的二手说法降级为待核验线索，不写进任何依赖判断。没有任何一条建议需要读者影响社区，也没有一条能做到。

**主要不确定性与适用边界：**
- 全部事实来自**一份二手快照**，其中一节（M5）由检索工具自己标注了可靠性警告。所有断言的可达状态为 `unchecked`（禁止检索），核验状态多为 `unresolved`——**链接没打开不等于断言为假，也不等于为真**。
- M6 是一条**否定性发现**（没找到 2026 年峰会结果、没找到 2026 年新冲突报道）。两次检索没找到，不等于不存在。本报告在任何地方都不把它当作"关系稳定"的正面证据。
- 结论对**系统边界**敏感：只看两个社区内部，采纳看起来是内部规则设计的结果；把厂商与下游发行版纳入边界，同一批事实更像外部推力驱动（见 §2 边界敏感性）。

**`needs_review` 对象：** 机制卡 MECH-3 的全部支撑断言（C12–C14，来自被标注警告的二手博客）标记为 `needs_review`；依赖它们的耦合判断（D6）与预测 P4 一并降权。

## 2. 系统边界：这个系统离开任何一方都不成立，但它的解释力依赖于把厂商放在里面还是外面

**分析对象**是 Rust-for-Linux 贡献者群体与 Linux 内核维护者群体之间的**互动关系**：规则如何被制定与接受、分歧如何被裁决、一方的选择如何改变另一方的成本。判别法通过：换掉 R4L 或换掉内核维护者，这个系统都不复存在（不同于"字节跳动换个竞争对手还是字节跳动"）。

**纳入的主体：** R4L 维护者（Miguel Ojeda）、持异议的资深内核开发者（Christoph Hellwig）、最终仲裁者（Linus Torvalds）、采纳侧子系统维护者（Dave Airlie / DRM、Greg Kroah-Hartman）、Maintainers Summit 作为裁决场所、官方政策页与邮件列表作为规则载体。

**排除的主体（以及排除谁承担了成本）：** 硬件厂商与下游发行版（NVIDIA/Nova、Google/Android、Apple silicon 驱动方、Debian、Ubuntu）被排除在"系统"之外，只作为环境。这个排除**不是中性的**——被排除的正是"谁在为 Rust 采纳提供资源与需求压力"。

**评价目标是谁的目标：** 本报告评的是**互动系统的可管理性与稳定性**，不是任何一方的胜负，也不是 Rust 的技术优劣。按关系系统的健康度语义：红线清晰、分歧有裁决渠道、共存叙事成立 = 高分；表面无声但规则效力存疑 = 未必高分。

**边界敏感性检查（`boundary_sensitivity`）：结论对边界敏感，必须写清依赖。**
把厂商与下游发行版**纳入**边界后：
- D2（克制的收益结构）从"内部规则设计使不参与者付出影响力代价"变为"外部资源与安全论证提供采纳收益"，机制 MECH-1 的解释份额下降；
- D6（耦合）显著恶化——下游 APT / Android / coreutils 的 Rust 依赖会把内核的语言选择变成跨生态的传染通道；
- **但**这些下游说法全部来自 M5 里被标注警告的二手来源（C12–C14），因此"纳入边界后结论变化"这件事本身目前只是**假设性的**，不是已观察的。

因此本报告的主干判断**建立在窄边界上**（只含两个社区），并明确声明：若 C12–C14 被独立核实，D6 与 MECH-1 的替代解释权重都需要重估。

## 3. 已知事实与未知：材料给了一次完整的冲突—裁决记录，但没给任何负担数据

### 3.1 关键证据（可追溯到具体摘录）

按断言级证据契约登记（完整表见 §8）。以下为载荷最大的几条：

- **C1**（M1）：Hellwig 质疑 Ojeda 政策文档的**效力**——"一个网页没有用，要生效必须进入内核树并获得广泛同意"，并指文档存在事实性错误。**关系：supports**（规则载体的合法性本身是争点）｜直接程度：indirect（快照转述邮件列表发言）。
- **C2**（M1）：Hellwig 称"没有任何子系统被强迫"的说法**与 Torvalds 的私下立场冲突**，"被 Linus 证明是错的"，并抱怨 Linus"在公开场合躲在'实验'这个说法后面"。**关系：supports**（这是 D3 公私信号不一致的唯一直接证据）｜indirect。
- **C3**（M1）：Hellwig 的结构性担忧是 **binding creep**——最终每个非叶子子系统都会被波及；他把 Rust wrapper 比作"癌性肿瘤"。**关系：supports**｜indirect。
- **C4**（M2）：Torvalds 立场——没有维护者被强迫学 Rust，但**放弃参与＝放弃对影响其子系统的 binding 与集成如何开发的影响力**。**关系：supports**（MECH-1 的规则核心）｜indirect。
- **C5**（M2）：**框架分歧**——Hellwig 认为 DMA 被迫接受 Rust；Linus 与 R4L 认为 DMA 的 Rust binding 只是 DMA 的**又一个使用者**，不属于 DMA 子系统本身。同一事实，两种归类。**关系：supports**（MECH-2 的核心）｜indirect。
- **C6**（M3）：2025-12 Ojeda 提交 "rust: conclude the Rust experiment"；2025 年东京 Maintainers Summit 认定实验结束；LWN 报道与会者共识为"内核中的 Rust 不再是实验性的，已成为核心组成部分"。**关系：supports**｜indirect（LWN 为 T2 级材料，经快照转述）。
- **C7**（M3）：Ojeda 同时告诫——不代表在每种配置、架构、工具链下都能工作，内核/上游 Rust/GCC 仍有大量工作。**关系：background**（对"实验结束＝问题解决"是 contradicts 方向的限定）。
- **C8**（M3）：Torvalds 明确 Rust 是**增补而非替代**；既有 C 代码不整体重写；乐观估计 2030 年 Rust 仍不到内核代码 5%，现实是数十年共存。**关系：supports**（D5 共存叙事的最强证据）。
- **C9**（M4）：Dave Airlie 称 DRM 大约**再有一年**就会要求新驱动用 Rust、不再接受 C。**关系：supports**（P1 的依据）。
- **C10**（M4）：GKH 称 Rust 驱动被证明比 C 驱动更安全、Rust/C 交互问题少于预期；2026-07-15 孟买重申 Rust 是永久组成部分、某些子系统很快将只接受 Rust 新代码，同时强调既有 C 代码不变。**关系：supports**。
- **C11**（M4）：官方政策页持续强调**子系统自治**——如何处理 Rust 由各子系统自行决定，不同子系统做法不同。**关系：supports**，但与 C9/C10 构成**未决张力**（见 §3.2）。
- **C12–C14**（M5）：Linux 7.0 于 2026-04-12 发布并移除 experimental 标签、Rust NVMe 与高速网络驱动进主线；Debian APT 自 2026-05 起有 hard Rust requirements；Android 16 在 6.12 内核用 Rust 内存分配器；Ubuntu 25.10 默认 Rust coreutils。**全部标 `needs_review`**——检索工具自己警告这些来自二手博客而非内核源。
- **C15**（M6）：**否定性发现**——未找到 2026 年 Maintainers Summit 结果（永久化决定来自 2025 年峰会）；未找到 2026 年内新一轮公开冲突的报道。**关系：background**，不作为正面证据使用。

**来源家族折叠（`source_family`）：** 本次全部证据折叠为 **5 个独立家族**——SF-lore（邮件列表争论：C1–C5）、SF-summit/LWN（C6–C9）、SF-talk（GKH 演讲：C10）、SF-policy（官方政策页：C11）、SF-blog-warned（C12–C14）。C15 是检索缺席，不构成家族。**同一快照内的重复提及不增加独立权重**——本报告在任何地方都没有把"材料里说了两次"当成两条证据。

### 3.2 未决冲突

1. **规则载体之争未见解决**：C1 提出"网页不算规则"，材料中**没有**任何后续显示该政策文档进入了内核树或获得了 Hellwig 所要求的"广泛同意"。2025 峰会的结论解决的是 Rust 的**地位**，不必然解决**政策文档的效力**。
2. **归类之争未见解决**：C5 的"binding 属于谁"是 2025 年冲突的真正引擎，材料中没有任何裁决它的记录。
3. **自治与强制的张力**：C11（子系统自治，谁都不被强迫）与 C9/C10（DRM 一年内只收 Rust 新驱动；某些子系统很快只接受 Rust）在**单个子系统内部**并不矛盾（子系统自治恰恰包含"自己决定只收 Rust"的权利），但对想给该子系统贡献 C 代码的开发者而言，结果与"被强迫"不可区分。这条张力材料未处理。

### 3.3 对当前决策有实质影响的未知（登记为 `unknown`，不用中间值填补）

- 维护者的**带宽与负担**数据（评审时间、CI 成本、工具链维护量）：`unknown`。政策文档以"带宽原因"作为不采纳的正当理由，但材料没有任何带宽的量化或定性观测。
- 有无**贡献者流失/退出**（Hirschman 意义上的 exit）：`unknown`。材料只记录了 voice（Hellwig 的公开反对），没有任何关于是否有人因此减少或停止维护的信息。
- **资金与雇主结构**（谁在为 R4L 与相关维护者付薪）：`unknown`。
- **2026 年的实际互动状态**：`unknown`。C15 只说明这两次检索没找到。
- Rust 代码占比的**实际测量口径**：`unknown`。C8 只给了一个前瞻性估计（2030 年 <5%），不是当前测量值。

## 4. 核心机制：一条规则把"强制"转成了"选择的代价"，而未解的归类问题决定它能否持续

按规范只深入 3 条机制，不做七维等长铺陈。

---

### MECH-1 · 自愿参与＋影响力代价：把强制冲突转成成本冲突

| 字段 | 内容 |
|---|---|
| **解释目标** | 为什么 2025 年这场看似不可调和的争议（"Rust 是否被强加给内核"）没有导致分裂或大规模抵制，而是在同年年底以一次程序性裁决收场。**时间窗口：** 2025-01 至 2025-12。**比较基准：** 需要全体维护者事前同意的替代规则设计。 |
| **机制链** | Torvalds 设定规则：任何维护者都不被强迫学 Rust，可继续只写 C（C4）→ 强制的道德争点被移除，反对者失去"被逼迫"这一最有动员力的立场 → 但同一规则附加代价：不参与者同时放弃对影响其子系统的 binding 如何开发的影响力（C4）→ 关心自己子系统演化方向的维护者面临**私人成本**而非**集体禁令** → 冲突从"该不该允许 Rust"（集体、二元、只能通过分裂解决）转为"我个人要不要为保留影响力而投入带宽"（个体、连续、可以各自决定）→ 子系统自治政策（C11）把这一决策下放到最小单元 → 系统层面不再需要达成统一意志，因而不再需要摊牌。 |
| **可观察变量** | ①公开要求"全内核统一政策"的呼吁数量（代理指标：邮件列表中要求树内政策文档的线程）；②子系统层面自主宣布采纳的事件数（C9、C10 各一次）；③是否出现集体性抵制或分叉动议（材料内为 0）。**数据获取：** 仅通过本快照，均为定性、无基线。**缺失：** 全部三个变量都没有时间序列。 |
| **支持断言** | C4（direct，SF-lore/summit）、C11（direct，SF-policy）、C6（indirect，SF-summit）、C9/C10（indirect，作为"自治被实际行使"的表现）。 |
| **反对/限定断言** | C1（政策文档效力被否定 → 规则可能并未真正生效，只是被最高权威口头背书）、C2（Linus 公私立场不一致的指控 → 规则的公开表述可能不是真实规则）、C5（归类之争使"你的子系统"这个概念本身不稳定 → 规则的适用对象没有定义清楚）。 |
| **替代解释（必须有）** | **ALT-1a｜权威裁决说：** 冲突平息与规则设计无关，只是 Torvalds 作为唯一终审者表态后，异议失去继续的场所——换任何一条规则、只要 Linus 支持，结果相同。**ALT-1b｜外部推力说：** 平息的真实原因是采纳侧的既成事实（Apple silicon、Android、Nova、NVMe、GPIO 抽象已进主线，C10 的安全论证），反对已无实际标的；规则只是给既成事实提供了事后说法。 |
| **鉴别预测** | 若 MECH-1 成立而非 ALT-1a：应能观察到**分歧在子系统层被各自消化**（不同子系统采取明显不同做法，且无人上诉到 Torvalds）——C11 已弱支持这一点。若 ALT-1a 成立：新争议应**再次直接上诉到 Torvalds 或峰会**，而不是在子系统内部解决。若 ALT-1b 成立：采纳节奏应与**厂商驱动发布节奏**同步，而与政策文本发布时点无关。**这三者在现有材料上无法区分**（见 §4.4 敏感性）。 |
| **失效条件** | ①出现某维护者虽已投入 Rust 却仍失去对本子系统 binding 的控制（代价支付了却没换来影响力）→ 机制的交换条件不成立；②出现自上而下的统一强制政策 → 自治前提被撤销；③C1 所指的政策文档被正式否决且无替代规则入树 → 规则从未真正存在。 |
| **行动影响** | 改变监测对象：不必再盯"是否有人反对 Rust"，应盯**上诉路径**——新争议是在子系统内部消化还是再次上升到 Torvalds/峰会。前者支持 MECH-1，后者支持 ALT-1a。 |

### MECH-2 · 归类未决：冲突真正的引擎没有被关掉，只是暂时没有被触发

| 字段 | 内容 |
|---|---|
| **解释目标** | 为什么"没有人被强迫"这条规则在 2025 年仍然引发了激烈冲突——以及为什么这个引擎在实验结束后依然存在。**时间窗口：** 2025 至 as_of。**比较基准：** 一个 binding 归属有明文定义的反事实内核。 |
| **机制链** | 规则说"不参与就不受影响"（C4）→ 但"影响"的范围取决于 **binding 算谁的**（C5）→ 归类没有明文标准：Hellwig 把 DMA 的 Rust binding 算作 DMA 子系统的一部分（因而 DMA 维护者被迫承担它），Linus 与 R4L 把它算作 DMA 的又一个使用者（因而不构成负担）→ 同一份代码在两种归类下产生**完全相反的义务分配** → 由于内核树是有向依赖图，binding 会沿依赖向上蔓延到非叶子子系统（C3 的 binding creep）→ 每一次新 binding 的落地都重新提出同一个未决问题 → 冲突具有**可重复触发**的结构，与参与者的善意无关。 |
| **可观察变量** | ①涉及"这个 binding 属于谁维护"的公开线程数（基线：材料记录 1 起，2025 年 DMA）；②非叶子子系统中出现 Rust binding 的事件；③是否出现书面的归属/维护责任规则（材料内：无）。 |
| **支持断言** | C5（direct，SF-lore，本机制唯一但直接的证据）、C3（direct，指出蔓延结构）、C1（indirect，规则未入树 → 归类无处被明文化）。 |

### 4.4 敏感性扰动（对 MECH-1 与 MECH-2 各做四项）

| 扰动 | MECH-1 | MECH-2 |
|---|---|---|
| **移除载荷最大的证据**（MECH-1 移除 C4；MECH-2 移除 C5） | 机制**坍塌**——C4 是"影响力代价"的唯一来源 | 机制**坍塌**——C5 是归类分歧的唯一直接记录 |
| **合并同源转载** | 无变化（C4 与 C11 属不同家族 SF-lore / SF-policy） | 无变化（C5 与 C3 同属 SF-lore，合并后**支撑降为一个家族**） |

**结论标注：**
- MECH-1：**依赖关键假设** —— 依赖单条断言 C4，且与 ALT-1a（权威裁决说）在现有材料上**无法区分**。
- MECH-2：**依赖关键假设** —— 全部直接支撑折叠后只剩一个来源家族（SF-lore），且其鉴别预测尚未有观察去检验。
- MECH-3：**证据不足以区分** —— 不承重。
- 三条机制中**没有一条**达到"结论稳健"。这是本次分析最重要的元判断，不能用一个综合置信分掩盖。

### 4.5 为何尚未失败（正向分析）

诊断缺陷之前先识别现在真正在维持这个关系的补偿机制——修掉任何一条都可能让关系更糟：

1. **共存叙事的具体化**：Torvalds 把承诺写成了可检验的具体形式——增补非替代、既有 C 代码不重写、2030 年仍 <5%、数十年共存（C8）。这不是善意声明，而是**降低对方最坏预期的技术性承诺**，直接压低了"被取代"这一存在性恐惧。
2. **最小决策单元 = 子系统**：自治政策（C11）让分歧不必上升为全局摊牌，天然限制了冲突的传染半径。
3. **仲裁者存在且已表态**：终审权集中（Torvalds），使争议有确定终点——代价是 C2 所指的公私不一致风险。
4. **实验标签的正式关闭**（C6）：把"随时可能被撤销"的不确定性移除，降低了双方的**押注风险**——反对方不再需要通过持续施压来促成撤回，支持方不再需要通过既成事实来防止撤回。
5. **技术回报已被采纳侧公开确认**（C10：更安全、交互问题少于预期）：为参与提供了带宽之外的正当理由。

**警告：** 补偿机制 1 与 4 都建立在**承诺的可信度**上，而 C2（公私立场不一致的指控）恰好攻击的是可信度本身。若公私不一致再次被公开指控，两条补偿机制会同时受损——这是本系统最需要盯住的耦合。

## 6. 三个解释都还活着：证据不能区分"缓和"与"下沉"（ACH）

三条互斥假说，回答"为什么 2026 年看起来是平静的"：

- **H1｜制度化收敛**：冲突已被规则与峰会实质解决，平静是真实缓和。
- **H2｜冲突下沉**：政策层关闭，但归类与负担分歧下沉到子系统层，公开度下降 ≠ 冲突消失。
- **H3｜外部推力主导**：采纳由厂商与下游需求推动，社区规则是事后追认；关系的稳定取决于外部推力是否持续。

| 证据 | 家族 | H1 | H2 | H3 |
|---|---|---|---|---|
| C4 自愿+代价规则 | SF-lore | C | C | N |
| C5 归类分歧未裁决 | SF-lore | **I** | C | N |
| C1 政策文档效力被否 | SF-lore | **I** | C | C |
| C6 峰会宣告实验结束 | SF-summit | C | C | C |
| C8 增补非替代 + 数十年共存 | SF-summit | C | C | N |
| C9 DRM 一年内只收 Rust | SF-summit | N | C | C |
| C10 GKH：更安全、永久组成部分 | SF-talk | C | N | C |
| C11 子系统自治 | SF-policy | C | C | N |
| C15 2026 无新冲突报道（缺席） | —（非家族） | C | C | N |

**判读（按规范：一条强 I 胜过十条 C；全 C 证据无鉴别力）：**
- H1 承受两条 I，但两条 I **同属 SF-lore 一个家族**、且都来自 2025 年（时点早于峰会裁决）→ 折叠后为**一次性、单家族**的不一致，未达排除阈值 → 状态 **stressed**，非 eliminated。
- H2 无 I → **active**（不可被现有证据排除，**不等于成立**）。
- H3 无 I，但支撑它的证据（C9、C10、C1）在 H2 下同样为 C → **鉴别力低** → **active but weakly discriminated**。
- **留一敏感性：** 移除 SF-lore 家族（C1–C5）后，H1 的全部 I 消失，三条假说状态相同 → **结论对单一家族高度敏感**。
- **C15 的编码：** 对 H1 与 H2 都是 C，因而**没有任何鉴别力**——这正是"没找到新冲突"无法支持"关系已缓和"的技术表述。

**三条假说全部存活。按规范，这本身就是核心发现：系统处于高不确定状态，现有证据不能区分缓和与下沉。** 报告不给出偏好解释，不把 ACH 分数当作后验概率。

## 7. 条件情景与可裁定预测：不给概率分布，只给可以被打脸的具体判断

### 7.1 条件情景（**不是概率分布**，两个情景**非互斥且非穷尽**）

**情景 A｜分层稳态（在 MECH-1 成立、归类惯例自发形成的条件下）：** 采纳继续沿子系统自治推进，DRM 类强制化只发生在采纳方自愿的子系统，归属问题被"谁写谁维护"惯例吸收。观察特征：新争议在子系统内消化、不上诉；无全局政策文件出台。**延迟量：** 子系统政策从宣示到落地约 12 个月量级（C9 的"再有一年"是唯一可用的时间刻度）。

**情景 B｜归属型复发（在 MECH-2 成立、且 binding 首次深入非叶子子系统的条件下）：** 冲突以完全不同的措辞回归——争的不是语言而是"接口改了谁跟着改""binding 坏了谁修"。观察特征：争议出现在非叶子子系统；出现要求把责任规则写入内核树的呼吁（C1 的诉求重现）。**阈值：** 单个非叶子子系统内出现 C 侧接口变更**强制**触发 Rust 侧同步修改的第一起案例。

不给概率：两个情景不互斥（B 可以在 A 之内局部发生），也不穷尽，且**无可陈述的 `probability_basis`**（无基础率、无模型、无专家范围）。按规范，"无法给出概率"是合格输出。

**稳健动作**（在两个情景下都成立）：把监测锚定在**归属与负担的语汇**上，而不是"Rust"这个词上；把 C12–C14 一律当作待核验。
