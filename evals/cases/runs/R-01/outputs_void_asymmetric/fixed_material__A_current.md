## 1. 执行摘要：这段关系已经赢了实验，但输了规则的书面化

**系统全息素描。** Rust-for-Linux（R4L）与 Linux 内核维护者之间的关系，在 2025 年底完成了一次真正的相变：Miguel Ojeda 的 "rust: conclude the Rust experiment" 补丁与东京 Maintainers Summit 的共识，把 Rust 从"实验"改写为"内核的核心组成部分"（M3）。这是关系系统里罕见的好结局——冲突没有被打赢，而是被**降格为工程分工**。但相变留下了一个未清算的残余：这段关系里最激烈的一次冲突（M1–M2）从来不是关于 Rust 好不好，而是关于**规则写在哪里、由谁宣布、算不算数**。Christoph Hellwig 的质疑精确命中了这一点——一个网页不是内核树里的文档，"没有子系统被强迫"的说法与 Torvalds 的私下立场不一致，而 Torvalds"在公开场合躲在'实验'这个说法后面"。实验的标签现在撕掉了，那句躲藏也就失效了；但**规则本身仍然没有落进内核树**。

**核心诊断结论：**

- **这是一段可管理性中上的关系（综合 3.3/5，趋势 ↑），不是一场危机。** 关系系统的健康度衡量可管理性而非友好度：这里有明确的降级阶梯（子系统自治）、明确的共存叙事（"增补而非替代"、数十年共存、2030 年前不到 5% 代码）、以及一个被双方接受的终局定性。这些是稳定关系的结构特征。
- **最弱的一维是信号保真（D3），不是技术分歧。** 冲突的引爆点是**同一事实的两种归类**：Hellwig 认为 DMA 被迫接受 Rust，Linus 与 R4L 认为 DMA 的 Rust binding 只是 DMA 的又一个使用者（M2）。争议双方没有共享的分类词汇，于是每一次 binding 提交都要重新谈判它"算不算入侵"。叠加"公开说实验、私下另作决定"的双轨信号，这是关系系统的典型 *信号反转* 前置条件。
- **真正的杠杆点是 D1（把交战规则写进内核树），而不是 D2 或 D6。** Hellwig 两年前提的诉求——"要生效必须进入内核树并获得广泛同意"——至今是这套治理里最便宜、最未被兑现的修复。它同时修 D1（红线文本化）、D3（消除公开/私下双轨）、D7（把 Torvalds 的个人裁量转成可引用的先例）。
- **下一次冲突有明确的时间坐标：DRM 的强制窗口。** Dave Airlie 说 DRM "大约再有一年"就只接受 Rust 新驱动（M4，2025 年底口径 → 指向 2026 年底前后）；Greg Kroah-Hartman 2026-07 重申"某些子系统很快将只接受 Rust 新代码"（M4）。当"子系统自治"第一次被用来**强制** Rust 而非**豁免** Rust，"没有人被强迫"这句共存叙事就会被从内部反证。这是本报告识别的一号风险节点。
- **高不确定状态：三个竞争假说全部存活（详见 §3）。** 材料里 2026 年既没有新一轮公开冲突的报道，也没有 2026 年峰会结果（M6）——**沉默既可以是和解，也可以是退出后的安静**。ACH 无法在现有证据下区分二者，这本身是本次诊断最重要的元发现。

**七维评分（雷达描述，[人工推演·未经工具校验]）：**

| 维度 | 分数 | 趋势 | 一句话 |
|---|---|---|---|
| D1 红线与交战规则 | 3 | ↑ | 规则实质清晰，法律形式缺位——政策活在网页而非内核树 |
| D2 克制的收益结构 | 3 | → | Torvalds 的"不参与=放弃影响力"是漂亮的机制设计，但带宽成本仍单边落在 C 维护者身上 |
| D3 信号保真与误判 | 2–3 | ↑ | 全系统最弱环：分类词汇不共享、公开/私下双轨。区间因假说而异（见 §3） |
| D4 棘轮与可持续性 | 4 | ↑ | 反棘轮：终局已定性、共存期以十年计、退出通道保留 |
| D5 共存叙事 | 4 | ↑ | "增补而非替代"被三个权威口径反复重申；"癌性肿瘤"式妖魔化是孤例而非主流 |
| D6 纠缠结构与传染通道 | 3 | ↓ | binding creep 是真实的耦合扩散；关键人单点（Ojeda / Torvalds / GKH）无冗余 |
| D7 极性与否决结构 | 3 | → | 极度不对称的单极结构 + 非正式行使，稳定但不可继承 |

雷达形状：**D4/D5 一侧饱满、D3/D1 一侧凹陷**——一个"目标共识已达成、程序共识未达成"的图形。这与规范 `scoring-calibration.md` 里的灾难签名（D5≤2 且 D2≤2）**不匹配**；也不完全命中生存区签名（D4≥4 且 D6≥4，此处 D6=3 未达标）。系统落在中位健康区的上沿。

## 2. 系统制图：这是一个单极仲裁 + 联邦自治的混合治理体

**2.1 关键行为体与其显性目标 / 显示性偏好**

| 行为体 | 声称的目标 | 材料显示的实际偏好 | 证据 |
|---|---|---|---|
| **Miguel Ojeda / R4L** | 让 Rust 在内核中被证明"技术、流程与**社会**层面"值得 | 主动降低对手成本：强调子系统可因"带宽原因"不采用；主动为成果降温（"不代表在每种配置、架构或工具链下都能工作"） | M1, M3 |
| **Linus Torvalds** | 保持内核可演进，不强迫任何人 | 保留个人终局裁量权，且**在公开表述与私下立场之间保留缝隙** | M2, M1 |
| **Christoph Hellwig（怀疑派代表）** | 防止 binding creep 与碎片化 | 要求**程序正当性**（进树、广泛同意），而不仅是结论；反对以网页代替治理 | M1 |
| **Greg Kroah-Hartman** | 驱动质量与安全 | 用实证背书（Rust 驱动更安全、互操作问题少于预期）并公开预告强制窗口 | M4 |
| **Dave Airlie / DRM** | 图形栈的长期可维护性 | 把子系统自治**反向使用**：自治不是拒绝 Rust 的盾牌，而是强制 Rust 的矛 | M4 |
| **下游发行版 / Android**（Debian、Ubuntu、Google） | —— | 通过 APT、coreutils、Rust 分配器、Android 专用驱动持续加压（**注：全部为二手来源，M5，不作为评分依据**） | M5 |

利益对齐处：三方（R4L / Torvalds / GKH）都要"增补而非替代"。分歧处：**谁承担过渡期的边际带宽成本**——R4L 说"可以不采用"，Hellwig 说"最终每个非叶子子系统都会被波及"。二者在逻辑上并不矛盾（前者说现在，后者说终局），这正是冲突反复的原因。

**2.2 规则层级**

- **正式规则**：内核树内的文档与 maintainer 流程；`rust/` 目录承载核心基础设施。
- **准正式规则**：官方政策页——"如何处理 Rust 由各子系统自行决定"。**它的效力正是 M1 争议的标的**：Hellwig 认为网页不构成规则。
- **非正式规则**：Torvalds 的私下立场；Maintainers Summit 的闭门共识（经 LWN 转述才公开）；"新驱动可用 Rust、既有 C 不重写"的默契。
- **元规则（谁能改规则）**：**Torvalds 单点**。这是全系统最集中的权力，也是全系统最没有继任设计的地方。

**2.3 资源流向与瓶颈**

负熵输入充足：Google、Apple silicon 社区、NVIDIA 方向的 Nova 驱动、NVMe、GPIO 抽象已进主线（M4）——Rust 侧持续输入人力与代码。**瓶颈不在 Rust 侧，在 C 侧维护者的评审带宽**：每一个 Rust binding 都要求一个 C 维护者理解足够多的 Rust 来评审它，而这份成本没有对应的补偿流。价值在 R4L 侧积累（安全性、新驱动生态），成本在既有子系统维护者侧沉淀。这是本系统唯一结构性的**收支不对称**。

**2.4 时相**

关系处于 **成熟化 / 制度固化期**（不是形成期，也不是危机期）。塑形事件序列：v6.1 合入 Rust（实验开始）→ 2025 政策文档争议（张力峰值）→ 2025-12 实验结束补丁 + 东京峰会定性（相变）→ 2026 沉默期（M6）。路径依赖约束：既有 C 代码不重写这条承诺已经不可逆，它把系统锁定在**数十年双语共存**这一条轨道上——好处是没有"全面转换"的悬崖，坏处是**双语维护的摩擦成为永久成本，而不是过渡成本**。

## 3. ACH：三个假说全部存活，因此"2026 年的平静"不能被读作和解

规范要求在维度诊断前做竞争假说分析。以下矩阵为 **[人工推演·未经 `ach_score.py` 计算]**，信源层级统一按 T2 处理（LWN 报道、峰会转述、公开演讲），M5 项按 T3 剔除。

**假说（互斥，回答"为什么这段关系现在是这个样子"）：**

- **H1 制度化成功论**：2025 年的冲突是渐进制度化中的正常定价摩擦；峰会定性解决了根本分歧，2026 年的平静是真实和解。
- **H2 权威压制论**：分歧没有被解决，而是被 Torvalds 的单极权威压下去了；平静源于怀疑派的**退出或沉默**，而非同意。
- **H3 成本延迟论**：分歧被推迟而非解决；binding creep 的真实成本尚未到达多数子系统，冲突会在采纳率跨过阈值（DRM 强制窗口）时以更高强度重现。

**证据矩阵：**

| 证据 | 层级 | H1 | H2 | H3 |
|---|---|---|---|---|
| E1 实验结束补丁 + 峰会共识"不再是实验性的"（M3） | T2 | **C** | C | C |
| E2 Hellwig："被 Linus 证明是错的"、指 Linus 公开躲在"实验"后（M1） | T2 | **I** | **C** | C |
| E3 DMA 归类的框架分歧未被裁决，只是各自表述（M2） | T2 | **I** | N | **C** |
| E4 Torvalds "不参与即放弃影响力"（M2） | T2 | C | **C** | N |
| E5 Airlie：DRM 一年内强制 Rust（M4） | T2 | N | N | **C** |
| E6 GKH 2026-07 重申永久性 + 强制预告（M4） | T2 | C | N | C |
| E7 官方政策页持续强调子系统自治、"不同子系统不同做法"（M4） | T2 | **C** | N | N |
| E8 2026 年未见新一轮公开冲突报道（M6，**否定性发现**） | 弱 | C | C | N |
| E9 2026 年峰会结果缺失（M6，**信息缺口而非证据**） | — | N | N | N |

**判定（一条强 I 胜过十条 C）：**

- **H1 = stressed。** 两条 T2 级 I（E2 的直接指控、E3 的未裁决分歧）。它没有被淘汰——E1/E7 是强 C——但"根本分歧已解决"这一断言在证据上过度了。
- **H2 = active。** 无 I。E4 是它的直接支撑：Torvalds 的机制本质是**把异议的成本转嫁给异议者**（你可以不参与，但你会失去影响力）。这是有效的治理，也是有效的压制，二者在行为上不可区分。
- **H3 = active。** 无 I，且拥有唯一一条指向未来的独立证据链（E5+E6）。
- **E8 无鉴别力**：三个假说都预测 2026 年表面平静（和解会安静、压制也会安静、成本未到也会安静）。**把"没有新冲突"读成"关系变好了"是本案最容易犯的推理错误。**

**规范规定的处置：全部假说存活 = 系统处于高不确定状态，这本身是关键发现。** 具体后果有二：

1. **D3 报评分区间 2–3**：在 H1 下信号通道是有效的（分歧被峰会消化），给 3；在 H2 下公开信道系统性失真（真实决策在私下、异议者已停止发声），给 2。现有证据不能区分。
2. 所有"关系在改善"的趋势判断（↑）都应读作**在 H1 为真的条件下**成立。

## 4. 七维诊断：目标共识已达成，程序共识没有

以下按规范「关系系统七维重诠释」的含义诊断。**健康度 = 这套互动关系的可管理性与稳定性，不是双方的友好程度。**

### D1 红线与交战规则：实质规则清晰，法律形式缺位 — **3/5，趋势 ↑**

这段关系的交战规则在**内容上**已经相当明确：新驱动与新子系统可用 Rust，既有 C 代码不整体重写，如何处理 Rust 由各子系统自行决定，不参与者不被强迫（M2、M3、M4）。以关系系统的标准看，这是一套**足以支撑长期共存的红线体系**——它给了弱势方（不想学 Rust 的 C 维护者）一个明确的、不需要谈判就能行使的退出权。

问题全部出在**形式**上。Hellwig 的质疑不是技术性的挑刺，而是关系系统里最本质的一类质疑：**规则的载体决定规则的可执行性**。他要求政策"进入内核树并获得广泛同意"（M1），因为内核树里的文档是可引用、可 diff、可在下一次争议中作为先例援引的；一个网页不是。当红线只存在于网页和某人的口头表述里，每一次边界摩擦都要重新回到人格化仲裁，而不是回到文本。

更深的一处侵蚀是**归类权的空缺**（M2）：DMA 的 Rust binding 究竟属于 DMA 子系统本身，还是 DMA 的又一个使用者？这不是一个可以由技术事实裁决的问题，而是一个**必须由规则约定的定义问题**。规则没有约定，于是每一方按自己的利益归类，同一份代码在一方眼里是入侵、在另一方眼里是普通调用者。关系系统里，红线的模糊从来不表现为"没有红线"，而表现为"双方各画各的"。

**病理模式：** *边界侵蚀*（软规则形式不足以承载已经变硬的实质约束）；*归类权真空*（本系统特有，未匹配已知库中任一模式，标记为**新型系统特有模式**）。
**趋势 ↑ 的理由：** 实验结束的补丁是一份**进了树的**文档，这是形式化的第一步。
**证据：** M1（Hellwig 对文档效力的质疑）、M2（DMA 归类分歧）、M3（补丁进树）、M4（政策页的子系统自治表述）。
**置信度：** 中高——争议本身有直接引述；对"是否已进树修复"的判断受材料截止限制。

### D2 克制的收益结构：一个漂亮的机制设计，压在一处未补偿的成本上 — **3/5，趋势 →**

Torvalds 的规则设计值得单独表扬，因为它做对了关系系统里最难的一件事：**让不合作的成本由不合作者自己承担，而不是由系统承担**。"没有维护者被强迫学 Rust，但选择不参与的维护者同时放弃对影响其子系统的 binding 如何开发的影响力"（M2）——这句话把一个潜在的零和对抗（强迫 vs 抵制）转成了一个**自选择均衡**：你可以退出，退出是免费的，但退出附带一个你自己愿意接受的代价。没有先发优势，没有"先动手者得利"的结构，因此**关系系统里最危险的激励倒置（先发激励）在这里不存在**。这是 D2 拿到 3 分而不是 2 分的主要原因。

但机制的另一半有缺口。R4L 侧的成本递减（工具成熟、GPIO 抽象进主线、NVMe 有贡献），收益递增（更安全的驱动、新硬件生态）；C 维护者侧则相反——每一个新 binding 都要求他们投入一份**没有对应回报的评审带宽**。政策文档专门为"带宽原因"开了豁免口（M1），说明设计者意识到了这个成本；但豁免不是补偿。系统对"愿意学 Rust 的 C 维护者"没有任何正向奖励渠道，只有对"不学的人"的惩罚（失去影响力）。**全惩罚、零奖励的激励结构在短期有效，在多轮博弈中会把中间派推向沉默而非合作**——这也正是 H2 难以被证伪的结构原因。

Airlie 的 DRM 宣告（M4）则把 D2 推到了一个新位置：当一个子系统用自治权**强制** Rust，退出选项对该子系统的新贡献者就消失了。此时"不被强迫"仍在字面上成立（你可以不给 DRM 提交驱动），但在实践上已经空心化。

**病理模式：** *成本-收益错配*（收益方与成本方不重合，且无转移支付渠道）。未构成 *激励倒置* 或 *Nash trap*。
**趋势 → 的理由：** 机制没有恶化，但也没有补上补偿侧；DRM 的强制窗口是一个待观察的扰动。
**证据：** M2、M1（带宽豁免条款）、M4（Airlie、GKH）。
**置信度：** 中——"C 维护者带宽成本未被补偿"是从材料结构推出的，材料没有直接的带宽数据。

### D3 信号保真与误判风险：全系统最弱环，且弱在一个可修的地方 — **2–3/5（区间因假说而异），趋势 ↑**

这段关系里所有真正的爆发点都是信号问题，不是立场问题。

**第一重失真是双轨信道。** Hellwig 的指控极其具体：文档里"没有任何子系统被强迫"的说法与 Torvalds 的私下立场冲突，"被 Linus 证明是错的"；而 Linus"在公开场合躲在'实验'这个说法后面"（M1）。在关系系统的语法里，这是**权威方同时维持两套不一致的信号**——公开信道用于降低对抗（"只是实验"），私下信道用于实际决策。这种结构的短期收益是给系统留缓冲，长期代价是**公开信道的信息含量归零**：一旦参与者学会"公开表述不代表真实立场"，他们就不再用公开表述来更新判断，而改用猜测和归因。Hellwig 说这种表述方式"不诚实"——从关系管理的角度，比不诚实更严重的是**不可用**。

**第二重失真是分类词汇不共享**（M2）。同一份 DMA binding，一方读成"我的子系统被迫接受 Rust"，一方读成"我的子系统多了一个使用者"。这不是分歧的两个立场，这是**同一个信号被读出两个相反的含义**——规范列的 *信号反转* 病理的教科书形态。1914 年七月危机的机制正是如此：动员被一方读成防御姿态、被另一方读成开战决定。这里没有战争风险，但有关系破裂风险：Hellwig 的"癌性肿瘤"比喻（M1）正是信号被读成入侵后的典型情绪产物。

**降级的一侧同样要记账。** Maintainers Summit 提供了一个真实的高带宽后台渠道，且它**产生了结论**（M3）；LWN 的报道把闭门共识公开化，降低了外部误读；Ojeda 主动在成果公布时附加告诫（"不代表在每种配置、架构或工具链下都能工作"，M3）——这是罕见的**反向信号管理**：赢家主动给自己的胜利降温，以避免对手把定性读成全面推进。这一条单独把 D3 从 2 分抬进了 2–3 区间。

**为什么给区间：** 在 H1 下，峰会消化了分歧、公开渠道恢复了信息量，给 3；在 H2 下，真实决策仍在私下、异议者已停止使用公开信道，2026 年的沉默恰恰是信道失效的证据而非改善的证据，给 2。E8（无新冲突报道）对这两种解读**没有鉴别力**。

**病理模式：** *信号反转*（关系系统专属，D3 主病理）；*双轨信道*（本系统特有的权威方失真形态，标记为**新型模式**）。
**证据：** M1（全部指控）、M2（框架分歧）、M3（峰会 + LWN + Ojeda 的降温告诫）、M6（否定性发现，无鉴别力）。
**置信度：** 中低——D3 是本报告受材料局限影响最大的一维；判断依赖于对**一位**怀疑派代表的引述，无法确认其代表性。

### D4 棘轮效应与可持续性：这段关系走的是反棘轮 — **4/5，趋势 ↑**

关系系统最常见的死法是升级棘轮：每一轮交手把"正常"的暴力基线往上抬一格。这段关系走的**恰好是反方向**，而且是有意为之。

三条证据构成了一个完整的降级阶梯：其一，**终局被明确封顶**——Torvalds 说 Rust 是增补而非替代，既有 C 代码不会被整体重写，乐观估计到 2030 年 Rust 也不到内核代码的 5%，现实是数十年共存（M3）。给一场结构性冲突设一个**十年尺度的时间表和一个 5% 的量化上限**，等于事先宣布"你担心的那个终局不会在你的职业生涯里到来"，这是消解对抗最有效的一步。其二，**退出通道被制度化保留**——子系统自治不是临时妥协而是持续政策（M4）。其三，**实验被正式结束而不是无限延期**（M3）：模糊状态本身是一种消耗，把它终结掉，双方就不必再为"这到底算不算数"反复交手。

系统同时在持续输入负熵：Google 的 Android 专用驱动、Apple silicon 的 Rust 贡献、开发中的 Nova、NVMe 贡献、已进主线的 GPIO 抽象（M4）。这不是一段消耗双方未来的关系，是一段**双方都在往里投资的关系**——投资本身是最强的稳定性信号，因为它意味着双方都预期这段关系会存在到投资回本。

扣分项：**5% 与"数十年"这两个数字目前没有承载它们的正式文本**（同 D1 的病灶），它们和"没人被强迫"一样活在口头表述里。一旦 Torvalds 缺席，这个封顶随时可以被重新解释。

**病理模式：** 未见 *升级棘轮*；未见 *更新剧场*（成果是真实代码而非仪式）。轻度 *承诺无载体*。
**证据：** M3（增补非替代、5%、数十年、实验结束）、M4（多来源实际贡献）。
**置信度：** 高——这一维的证据最密集、最一致。

### D5 共存叙事：三个权威口径讲同一个故事，妖魔化是孤例 — **4/5，趋势 ↑**

关系系统的 1 分区是相互否定存在权（"大撒旦"式）。这段关系离那里很远，且距离在拉大。**"增补而非替代"这一句共存叙事被系统里三个最有分量的口径反复重申**：Torvalds（M3）、Greg Kroah-Hartman（2026-07 孟买，M4）、以及 Ojeda 自己（M1 的带宽豁免、M3 的降温告诫）。GKH 的表述尤其值得注意——他在宣布"某些子系统很快将只接受 Rust 新代码"的**同一场演讲里**强调既有 C 代码保持不变（M4）。这是标准的关系管理动作：每一次推进都配一次安抚，让推进不被读成蚕食。

叙事同时对外成立：峰会共识（Rust 已是内核核心组成部分）被 LWN 这样的权威第三方报道并接受，意味着**外部观察者对这个互动格局的现状规则是承认的**——关系没有正当性赤字。

扣分项是 Hellwig 的"癌性肿瘤"比喻（M1）。以关系系统的读法，把对方的产物描述为一种在体内扩散、必须切除的恶性组织，是**否定共存可能性的语言**——不是"我不喜欢这个方案"，而是"这个东西存在本身就是病"。它没有把 D5 拉到 3 分以下，因为它是孤例、来自一位个人而非一个阵营的共同表述，且此后两年未见同类升级（M6）。但它标记了这段关系里**存在一个不接受共存叙事的少数派**，且这个少数派恰好是技术上最有分量的人之一。

**病理模式：** 局部 *妖魔化语言*，未构成 *共存叙事归零*。
**证据：** M3、M4（三口径重申）、M1（癌性肿瘤比喻）、M6（无后续升级）。
**置信度：** 中高。

### D6 纠缠结构与传染通道：唯一趋势向下的一维 — **3/5，趋势 ↓**

Hellwig 的 binding creep 论证在结构上是**正确的**，无论人们喜不喜欢它的措辞：Rust wrapper 需要它所包装的 C 侧接口保持某种稳定性，因此每一个 binding 都在两个子系统之间创造一条**新的、双向的耦合边**。"最终每个非叶子子系统都会被波及"（M1）不是危言耸听，而是对拓扑扩散的直接推论——叶子子系统可以独善其身，中间层不行。这条通道随着采纳率上升而**单调收紧**，这是本报告给出 ↓ 趋势的唯一一维。

第二条传染通道是**关键人单点**。这段关系目前依赖三个不可替代的个人：Ojeda（R4L 侧的唯一政策发言人与补丁提交者）、Torvalds（唯一的终局仲裁者与元规则持有者）、GKH（跨阵营的实证背书者与预告者）。材料里没有任何一处显示存在这三个角色的**继任或冗余安排**。任一节点缺席，这段关系会立刻退回到"规则不明 + 无人能裁"的状态——而这正是 2025 年冲突的初始条件。

第三条是**下游压力通道**：Debian 的 APT hard Rust requirements、Android 16 的 Rust 分配器、Ubuntu 25.10 的 Rust coreutils（M5）。如果属实，它们会把上游的自治决定变成**下游既成事实的追认压力**，实质压缩子系统自治的真实空间。**但这三条全部来自二手来源，材料自身已作可靠性警示，因此不计入评分依据，仅作为待验证的传染通道登记。**

缓冲：数十年共存的时间表本身是最大的缓冲——耦合是渐进收紧而非突然收紧，系统有时间在每一格上重新谈判。这是 D6 保住 3 分的原因。

**病理模式：** *依赖陷阱*（关键人单点，无冗余）；*级联架构*雏形（binding creep 的拓扑扩散）。
**证据：** M1（binding creep 论证）、M4（采纳面在扩大）、M5（下游通道，**不计分**）。
**置信度：** 中——拓扑推论可靠，关键人单点是从材料中"只出现这三个名字"推出的**弱证据**，可能是材料覆盖偏差而非真实结构。

### D7 极性与否决结构：稳定的单极，但不可继承 — **3/5，趋势 →**

力量对比高度不对称，且不对称是**已固化的**：Torvalds 持有元规则（谁能改规则）、终局裁量权，且以非正式方式行使（M1、M2）。这种结构的好处不能被低估——关系系统里，**一个可信的、双方都接受的仲裁者是最有效的升级阻断器**。2025 年的争议之所以在一年内落地为一份补丁而不是一场分裂，正是因为存在一个所有人都知道他说了算的节点。

代价有三层。其一，**权力-问责不对称**：Torvalds 的决定在私下作出、在公开被"实验"的措辞遮蔽（M1），这意味着决定的作出者不必在公开场合为决定辩护，异议者也无从在公开场合挑战它。其二，**否决权的性质正在改变**：子系统维护者的否决权原本是**防御性**的（我可以拒绝 Rust），Airlie 的 DRM 宣告（M4）把它变成了**攻击性**的（我可以拒绝 C）。同一项自治权在两个方向上都能用，而系统里没有任何规则区分这两种用法——这是 D7 与 D1 的接缝处，也是下一次冲突最可能的爆点。其三，**没有继任设计**：单极结构的稳定性完全依赖极点的在位，材料里看不到任何关于"Torvalds 不在时谁裁决 Rust 争议"的制度安排。

**病理模式：** *影子权力结构*（正式表述与实际决策路径不一致，M1 直接指控）；*继任真空*（未见任何制度化过渡机制）。未见 *否决陷阱*——系统仍能作出决定，2025 年的补丁就是证据。
**证据：** M1、M2、M4。
**置信度：** 中高（对现状），低（对继任安排——这是**信息缺口**，不是"不存在"的证据）。

- **⚖️ 拮抗 L3「强制采纳 vs 自愿红线」（D2 ↔ D1，负边）。** 提高采纳速度的每一个动作（DRM 强制、GKH 预告）都在削弱"没有人被强迫"这条红线；反之，严守红线会让采纳停留在自愿者范围内。**改善 D2 会付出 D1 的代价**，反之亦然。这不是可以两全的取舍，报告在 §8 处方部分给出优先级裁定。

**Step 3c 杠杆点排序 [人工推演·排序未经工具校验]：** 按回路参与次数为主键（Meadows）——
1. **D1（参与 L1、L3，且是 L1 中唯一可由单方动作改变的环）** ← **首要杠杆点**
2. D3（参与 L1、Weak 对多）
3. D7（参与 L1，但改变它需要人事而非制度动作，可行性最低）
4. D4 / D5（参与 L2，已在良性区间，维持即可）

**为什么杠杆点是 D1 而不是 D3 或 D7：** L1 这条恶性回路里，D7（换掉或约束 Torvalds）不可行，D3（改善信号）没有独立抓手——信号失真是规则真空的**症状**，不是原因。只有 D1 有一个明确、便宜、单方即可执行的动作：**把规则写进内核树**。这也解释了为什么 Hellwig 的原始诉求虽然措辞恶劣，在系统工程上却是正确的。

**Step 3d 已知模式匹配：** 命中 *Power-information doom loop*（7×3，以 L1 的变体形态）。**未命中** *Trust death spiral*、*Innovation theater trap*、*Legitimacy-coupling cascade*——这三者都要求 D5 显著劣化，而本系统 D5=4。新增两个**系统特有模式**：「归类权真空」（D1）与「双轨信道」（D3）。

## 6. 历史类比：结构上最像美苏缓和，不像 1914

**[人工推演·`find_analogies()` 未运行，以下为定性匹配，无相似度分数，请勿当作工具输出引用。]**

按七维形状（D4/D5 高、D3/D1 低、D7 单极不对称、D6 中等且收紧）定性匹配规范提及的 `relational` 案例库：

- **最接近：美苏缓和（US-USSR détente）。** 共同结构：双方都已放弃"消灭对方"的终局叙事（对应"增补而非替代"）、建立了可用的后台渠道（峰会 ≈ 首脑会晤）、把冲突转成可管理的长期共存、并用**可验证的量化限制**给对抗封顶（军控条约 ≈ 5%/数十年）。**关键差异**：缓和的封顶写进了**条约文本**，而这里的封顶只在口头表述里——这正是本报告的一号处方所指。缓和的教训也在这里：**当承诺缺乏文本载体、且依赖特定领导人时，它会随领导层更替而蒸发。**
- **次接近：埃以冷和平（Egypt-Israel cold peace）。** 共同结构：冲突已被制度性终结，但一方的核心圈层从未在情感上接受共存（对应 Hellwig 的"癌性肿瘤"）；关系稳定但冷。差异：冷和平有一份和约，本系统没有。
- **明确**不像**：1914 七月危机。** 尽管 D3 有信号反转的病理形态，但 1914 的两个必要条件在这里**都不存在**——没有先发优势（D2 的自选择均衡消除了它），没有刚性纠缠迫使各方无法单独踩刹车（子系统自治始终提供单边退出）。**这一点值得强调，因为 D3 的病理容易诱导出过度悲观的类比。**

**结构性警示信号检查：** top-3 类比中两个（缓和、冷和平）的结局方向是"长期低烈度稳定"而非"崩溃"，不构成规范所说的"同向坏结局"警示。

## 7. 一号风险节点：DRM 的强制窗口会从内部反证"没有人被强迫"

规范要求识别 1–3 个最关键的风险节点。

### 风险节点 A（首要）：「子系统自治」这条规则同时授权豁免与强制，而无人裁决过它能否用于强制

- **精确定位：** 不是"DRM 要用 Rust"这件事，而是**同一条自治规则被用于两个相反方向时缺乏归类裁决**——与 M2 的 DMA 归类分歧同源。当 Airlie 的 DRM 在承诺的窗口内开始拒收 C 新驱动（M4，2025 年底口径指向 2026 年底前后），"没有维护者被强迫"这句话在字面上仍真、在实践上已假。
- **失败级联：** DRM 拒收 C 新驱动 → 怀疑派指出"强迫"已经发生、且是通过官方政策的漏洞发生的 → Torvalds 必须公开裁决（自治权能否用于强制）→ 无论裁决方向如何，都要推翻一份既有的公开表述 → L1 回路被激活：无文本可援引 → 回到人格化仲裁 → 争议扩散到其他准备跟进的子系统 → D1、D3、D5 同时受压。
- **时间窗口：** 最早 2026 年内，指向 2026Q4–2027 上半年（基于 M4 的"再有一年"口径 + GKH 2026-07 的"很快"）。**材料对 2026 年后半段无覆盖，此估计不确定性高。**
- **触发条件：** 第一份被 DRM 以"我们只收 Rust"为由拒绝的 C 驱动补丁公开出现在邮件列表上。

### 风险节点 B：单极仲裁结构无继任设计

- **精确定位：** 封顶承诺（5%、数十年、增补非替代）与红线（没有人被强迫）**全部由同一个未被文本化的个人权威承载**。
- **失败级联：** 极点缺席 → L2 良性回路的可信度基础消失（封顶变成"某人曾经说过"）→ 各子系统按自身利益重新解释自治权 → D1 碎片化 → 冲突从一个中心争议裂成 N 个子系统级争议，且**没有任何机构能再作出统一裁决**。
- **时间窗口：** 不可预测（外生事件驱动），但**发生概率随时间单调上升**。
- **触发条件：** 任何导致 Torvalds 长期缺席的事件；或 Ojeda 离开 R4L 政策角色。

### 风险节点 C（次要）：下游既成事实倒逼上游自治

- **精确定位：** 若 Debian/Android/Ubuntu 的 Rust 硬依赖属实（M5），上游"子系统可以不采用"的自治将被下游发行版的事实要求架空。
- **状态：** **证据不足以定级。** M5 的三条全部来自二手来源、材料自身已作可靠性警示。**登记为待验证通道，不进入评分与情景概率。**

## 8. 演化沙盘：七成概率走向"写下来的共存"，两成概率在强制窗口重新点火

### 8.1 无干预自然演化（1–3 年，至 2029-09）

| 情景 | 概率 | 描述 |
|---|---|---|
| **自组织相变（新吸引子）** | **65%** | DRM 的强制窗口迫使系统作出一次归类裁决，裁决过程本身把规则文本化（进树文档、明确"强制型自治"的边界）。L1 恶性回路被 D1 的一次性修复打断，系统进入"规则可引用 + 单极仲裁退居后台"的稳定态。**支撑：D4/D5 已在 4 分、L2 良性回路在运转、双方都在持续投资。** |
| **剧烈分岔（冲突/分裂）** | **22%** | 强制窗口引发的争议在无文本可援引的情况下升级，Hellwig 式的碎片化担忧被 DRM 的实际做法证实，怀疑派子系统联合抵制或事实分叉治理（各子系统各行其是、无共同政策）。**支撑：L1 恶性回路仍在运转、D1 无载体、风险节点 A 有确定的时间坐标。** 注意：这里的"分裂"是**治理层的碎片化**，不是内核代码的 fork——后者被 D6 的渐进耦合与 D4 的时间表强烈抑制。 |
| **热寂（惰性均衡）** | **13%** | 无人再推进也无人再反对：Rust 采纳停在少数驱动子系统，binding 工作因 C 侧带宽未被补偿而缓慢窒息，关系变成互不干涉的冷共存。**支撑：D2 的成本-收益错配未修复、H2（异议者已沉默）无法被证伪。** |

概率依据：危险区签名未命中、生存区签名部分命中（D4≥4 达标、D6≥4 不达标）→ 好结局占优但不压倒；风险节点 A 有明确触发时点 → 剧烈分岔不可忽略。**这些概率是基于单一材料源的主观赋值，不是模型输出。**

### 8.2 高杠杆干预处方

**处方对象：** 内核治理层（Torvalds、Ojeda、子系统维护者群体）。所有处方按规范要求给出作用机制、二阶效应、阻力来源，并标注传导注释。

---

**P1｜把 Rust 政策以 patch 形式提交进内核树，并在其中显式裁决"归类规则"与"强制型自治"（目标 D1，杠杆点首位；优先级最高）**

- **具体动作（周一早上就能做的）：** 由 Ojeda 提交一份 `Documentation/` 下的 patch，走完正常评审与 acked-by 流程，内容必须包含三条现在只存在于口头的规则：(a) **归类规则**——一个子系统的 Rust binding 属于该子系统还是属于其使用者，判定标准是什么（直接解决 M2 的 DMA 分歧）；(b) **强制型自治的边界**——子系统自治权是否包含"拒收 C 新代码"，若包含，前置条件是什么（提前公告期、既有 C 代码保障、跨子系统协调义务）；(c) **封顶承诺的书面化**——增补非替代、既有 C 不重写，落成可引用的文本而非某人的表述。
- **作用机制：** L1 恶性回路的三条边里，只有 D1→D3 这条可以由单方动作切断。规则一旦可引用，下一次摩擦就在文本层解决，不必上诉到人；仲裁需求下降，权力集中的自我强化随之减弱。**这不是"改善沟通"，是把仲裁的成本从人格转移到文本。**
- **正向溢出：** D3（公开信道恢复信息量，双轨信号无处藏身）、D7（Torvalds 的裁量转成可引用先例，问责性提升）、D5（共存叙事获得文本背书，"癌性肿瘤"式指控失去弹药）。
- **负向溢出：** **D7 会短期承压**——把裁量权文本化等于自缚，权力持有者的灵活性下降；且写下来的规则可能在写作过程中暴露此前被模糊掩盖的分歧，**争议会提前而非消失**。这种劣化是**可控的**（一次性、有限期），因为它把一场必然发生的争议从危机时刻挪到了平静时刻。
- **阻力来源：** Torvalds 本人（模糊性对仲裁者有价值）；以及任何认为"现在没冲突、别去捅"的维护者。
- **处方冲突：** 与 P2 直接冲突（见 P2 与下方交叉检查）。

---

**P2｜要求任何计划转向"只收 Rust"的子系统提前 12 个月在内核树内公告，并附带既有 C 代码的维护承诺（目标 D1×D2 接缝，直击风险节点 A）**

- **具体动作：** DRM 是第一个实例，因此就以 DRM 为模板：Airlie 把口头的"再有一年"改成一份进树的、有生效日期的子系统政策补丁，并在同一份文档里承诺既有 C 驱动的维护年限。此后任何子系统效仿须走同一流程。
- **作用机制：** 强制本身不是问题，**无预告、无程序的强制才是问题**。12 个月的公告期把一次可能被读成"背叛承诺"的动作，转成一次被读成"按规则行使自治权"的动作——这正是 D3 信号反转的解药：给对方足够时间和足够信息，使其无法把这个动作读成敌意。
- **正向溢出：** D3（消除突袭式误读）、D5（证明"不被强迫"与"子系统可以强制"两句话可以在同一套规则下共存）、D6（给依赖该子系统的 C 贡献者时间重新规划，降低级联）。
- **负向溢出：** **D2 承压**——12 个月的缓冲会拖慢采纳节奏，削弱 Rust 侧的推进动能；对于已经准备好的子系统，这是纯粹的等待成本。劣化是**结构性的**（每一次强制都要付一次），不是一次性的。
- **阻力来源：** R4L 侧的推进者与已准备好切换的子系统维护者（他们会正确地指出这拖慢了安全收益的兑现）。
- **处方冲突：** **与 P1 在 D2 方向上冲突**：P1 把规则写死会限制强制，P2 给强制加缓冲期同样限制采纳速度——二者叠加会显著拖慢 Rust 推进。裁定见交叉检查。

---

**P3｜为跨语言评审带宽建立显性补偿渠道（目标 D2 的成本-收益错配）**

- **具体动作：** R4L 侧承诺对每一个提交给 C 子系统的 binding 附带三件东西：一份面向 C 维护者的评审指南（这段 Rust 在做什么、哪些不变量需要 C 侧保证）、一位指定的 Rust 侧共同维护者（binding 出问题时由他先响应而非由 C 维护者）、以及 binding 的长期维护承诺。以书面形式写进 MAINTAINERS 或 binding 的文档头。
- **作用机制：** 现有激励结构是**全惩罚、零奖励**（不参与要失去影响力，参与没有补偿）。这一条把参与的边际成本实际降低，使中间派可以在不学完 Rust 的情况下参与——它攻击的是 H2 得以成立的结构条件（中间派被推向沉默）。
- **正向溢出：** D6（Rust 侧共同维护者是关键人单点的部分冗余）、D5（用行动而非口号证明"增补而非替代"）、D3（评审指南本身是共享分类词汇的载体，直击 M2 的归类分歧）。
- **负向溢出：** D6 轻微——共同维护者制度增加了跨子系统的人员纠缠，本质上是**用组织耦合换技术耦合的可管理性**。可控。
- **阻力来源：** R4L 侧的人力约束（这是实打实的额外工作量）。
- **处方冲突：** 无。**这是唯一一条与其他处方零冲突、且同时改善三个维度的处方。**

---

**P4｜为"Torvalds 不在时谁裁决 Rust 争议"建立明示的备用机制（目标 D7/风险节点 B）**

- **具体动作：** 不需要改变现有权力结构，只需要在 P1 的同一份文档里加一节：当终局仲裁不可用时，Rust 政策争议的处理路径是什么（例如：由 Maintainers Summit 多数意见暂行，直至下一次峰会复议）。
- **作用机制：** 单极结构的脆弱性不在于集中，而在于**没有降级路径**。写下一条备用路径，L2 良性回路（封顶承诺的可信度）就不再全押在一个人身上。
- **正向溢出：** D4（封顶承诺的可持续性提高）、D5（承诺变得可继承）、D1。
- **负向溢出：** D7 政治敏感——讨论继任在任何单极系统里都是禁忌话题，讨论本身可能被读成挑战。**这是本组处方里执行风险最高的一条。**
- **阻力来源：** 几乎所有人，出于礼貌与忌讳。
- **可行性评级：** 低。**但影响评级最高，因为它是唯一针对风险节点 B 的处方。**

---

**处方交叉检查（规范 §5.2 要求）：**

1. **单一维度被多条处方同时恶化？** 有：**D2 被 P1 和 P2 同时拖累**（两者都在给采纳速度加约束）。这是本组处方最大的集中风险。**缓解：P3 从相反方向改善 D2**（降低参与成本），三者叠加后 D2 的净效应接近中性——这是 P3 必须与 P1/P2 同批执行的原因，它不是可选项。
2. **不可调和的方向性冲突？** P1（把规则写死）与 P2（给强制留通道）在表面上矛盾——前者倾向限制强制，后者承认强制合法。**裁定：不矛盾，应合并执行。** P1 的正确写法不是"禁止强制"，而是"规定强制的程序"，P2 就是那个程序。**若被迫二选一，优先 P1**——因为 D1 是杠杆点（参与 L1、L3 两条回路），而 P2 只处理其中一个具体实例。
3. **优先级排序：** **P1（影响高·可行性中·紧迫性高）> P3（影响中·可行性高·紧迫性中）> P2（影响中·可行性中·紧迫性高，绑定风险节点 A 的时间窗）> P4（影响高·可行性低·紧迫性低但单调上升）。**

### 8.3 监控仪表板：五个先行指标

| 指标 | 测量方法 | 危险阈值 | 健康阈值 |
|---|---|---|---|
| **1. 规则的载体位置**（D1，杠杆点直读） | 检查 Rust 政策是否以 patch 形式进入内核树、是否有多位子系统维护者的 acked-by | 到 2027-09 仍只存在于网页 | 进树且有 ≥5 个非 R4L 子系统维护者 acked-by |
| **2. 归类争议复发频率**（D3，最灵敏的早期信号） | 统计邮件列表上"这个 binding 属不属于我的子系统"类型的争论次数（M2 的同型冲突） | 每季度 ≥2 起且无一起被援引先例解决 | 出现"按 XX 文档第 N 条"式的援引解决 |
| **3. 强制型自治的程序合规**（风险节点 A 的直读指标） | 观察 DRM 转向时是否有提前公告 + 既有 C 维护承诺 | 无预告直接拒收 C 新驱动 | ≥6 个月公告 + 书面 C 维护承诺 |
| **4. 权威口径的一致性**（D3 双轨信道） | 对比 Torvalds/GKH/Ojeda 在公开场合的表述与实际合并决定是否一致；特别关注是否再次出现"公开说 A、实际做 B"的指控 | 一年内出现新的"公开/私下不一致"公开指控 | 连续两年无此类指控，且公开表述可预测实际决定 |
| **5. 共存叙事的语言温度**（D5，最便宜的监测） | 抽样怀疑派维护者的公开表述，看是否出现"癌性肿瘤"级别的否定存在权的比喻，以及这类表述是否从个人扩散为群体口径 | 出现 ≥2 位有分量的维护者使用同类否定性语言 | 分歧表述保持在技术论证层面 |
