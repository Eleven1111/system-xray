# Rust-for-Linux 与内核维护者：互动格局分析

**as_of：2026-09-09 ｜ 唯一依据：R-01 固定材料快照（未做任何新检索）**

## 一、结论先行

这套关系在 2025 年底完成了一次**性质变更**：从"可被撤销的实验"变成"已确权的常驻方"。2025 年东京 Maintainers Summit 认定实验结束，Ojeda 提交 "rust: conclude the Rust experiment"，LWN 报道与会者共识是内核中的 Rust 已成为核心组成部分。此后材料里**没有**出现新一轮公开冲突的报道（M6）——这既可能意味着争议真的降温，也可能只是检索没覆盖到，不宜当作"和解已完成"的证据。

真正值得关注的不是"Rust 会不会留下"（已定），而是**留下之后，权力如何在两个社区间重新分配**。

## 二、这套关系的运行机制

**1. 支撑关系的是一条交易条款，而非共识。**
Torvalds 的公式很明确：没人被强迫学 Rust，可以只写 C；但拒绝参与的维护者**同时放弃**对影响其子系统的 binding 与集成如何演进的影响力（M2）。这是一个"自愿加入、代价自负"的设计——它避免了正面强制，却把压力转成了长期的、渐进的：不参与的成本随 Rust 覆盖面扩大而单调上升。

**2. 冲突的真实层面是分类权，不是技术。**
M2 里那处分歧最能说明问题：Hellwig 认为 DMA 被迫接受 Rust；Linus 与 R4L 认为 DMA 的 Rust binding 只是 DMA 的**又一个使用者**，不属于 DMA 子系统本身。同一事实、两种归类，冲突由此产生。归类决定了谁承担维护负担、谁有否决权——所以这不是措辞之争，是管辖权之争。

**3. 治理程序本身是争议标的。**
Hellwig 对政策文档的第一反应不是反驳内容，而是质疑其**效力**：一个网页不算数，要生效必须进内核树并获广泛同意（M1）。他还指控 Linus 公开躲在"实验"说法后面、私下另作决定——即"文档所写与实际立场不一致"。这类指控的破坏力大于任何具体技术分歧：它攻击的是这套关系的**可信度基础**。

**4. 反对意见有结构性内核，不能当作情绪。**
binding creep——最终每个非叶子子系统都会被波及，Rust wrapper 像在子系统间扩散的"癌性肿瘤"造成碎片化（M1）。这是一个可证伪的预测，而 M4 的走向恰恰在验证它的前半段：DRM 维护者 Airlie 称大约再有一年就要求新驱动用 Rust、不再接受 C；GKH 在 2026-07 重申某些子系统很快将只接受 Rust 新代码。**"自愿"在子系统层面正在变成"事实强制"**，只不过强制的施加者是各子系统自己，不是中央。

## 三、当前格局：三层压力不均衡

- **中央层**：立场稳定，且刻意留缓冲——Rust 是增补非替代，既有 C 不重写，乐观估计到 2030 年 Rust 也不到内核代码的 5%，现实是数十年共存（M3）。
- **子系统层**：分化最快。DRM 走在最前，NVMe、GPIO、Apple silicon、Google 的 Android 专用驱动、Nova 各有进展（M4）。官方政策页仍强调子系统自治。
- **个体维护者层**：材料只呈现了 Hellwig 一个具名反对者。**沉默的中间层有多大、态度如何，材料没有覆盖**——这是本次分析最大的盲区。

## 四、风险

1. **"自治"与"事实强制"的裂口扩大。** 中央说自治，子系统在设定硬门槛。等第一个子系统真的拒收 C 新驱动时，M1 的争议大概率以新形式复现。
2. **私下立场与公开表述的落差。** Hellwig 的诚信指控若未被制度性回应，会持续侵蚀政策文档的权威——而政策文档正是这套关系唯一的成文接口。
3. **人员集中度。** 关系的两端各由少数关键人（Ojeda、Torvalds、GKH、Airlie）承载。**继任与总线因子问题材料完全没有覆盖**，但从材料结构看这是显性脆弱点。
4. **Ojeda 自己划出的红线常被忽略：** 永久化不等于在每种配置、架构、工具链下可用（M3）。把"实验结束"读成"工程完成"，会造成期望错配。

## 五、建议

- 观察的**首要指标**不是 Rust 代码占比，而是：(a) 第一个正式拒收 C 新驱动的子系统何时出现、以何种程序确立；(b) 政策文档是否最终进入内核树（这是 Hellwig 提出的合法性门槛，也是最干净的判断点）。
- 把 binding 的归类规则**写成成文标准**，比逐案争论更能减少复发冲突——DMA 之争的本质是缺少这条规则。
- 引用注意：M5 的 "Linux 7.0 于 2026-04-12 移除 experimental 标签"、Debian APT hard Rust requirements、Android 16、Ubuntu 25.10 coreutils 等说法**均来自二手来源，检索工具自身已标注警告**，本报告不作为事实依据使用。
- 常见错误更正：永久化决定来自 **2025 年**峰会；材料中**没有** 2026 年 Maintainers Summit 的任何结果（M6），不要写成 2026 年的决定。
