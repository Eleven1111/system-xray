# Rust-for-Linux × 内核维护者：一场关于"归类权"的关系诊断

**系统类型：** relational（对象是两个社区的互动格局，换掉任一方即不存在）
**as_of：** 2026-09-09 ｜ **完整性：** `partial`（单一材料快照，无独立信源核验）

## 1. 决策摘要：规则已经稳定，争的是谁来给代码分类

这段关系在 2025 年底完成了一次**制度化**——"实验"标签被 2025 年东京 Maintainers Summit 正式撤销，Rust 成为内核核心组成部分（M3）。但冲突并未随之消解，因为真正的争点从来不是"要不要 Rust"，而是**一段 Rust binding 该被归为哪个子系统的维护负担**。Torvalds 的裁决把 DMA 的 Rust binding 归类为 DMA 的"又一个使用者"，Hellwig 则视其为强加于 DMA 子系统本身（M2）。同一事实、两种归类，这是全部张力的源头。

结论：这是一段**可管理性中等偏上、仲裁程序合法性偏弱**的关系。它不会破裂，最可能的失败形态不是分裂，而是**子系统维护者的静默退出**——退出成本已被规则设计得低于对抗成本。

## 2. 系统边界与主体

三个主体而非两个：R4L 贡献者（Ojeda 等）、既有 C 维护者（Hellwig 为其中最直言者）、**唯一的仲裁者 Torvalds**。第三方不是中立调解人而是规则制定者——这是本系统区别于典型对抗关系的结构特征。

**边界敏感性：** 若把下游发行版（Debian APT、Android、Ubuntu coreutils，M5）纳入系统，会多出"外部需求倒逼内核采纳"的压力通道，D2 判断随之改变。但这些说法均来自材料自标的二手来源，**本报告不纳入**，结论仅对"内核树内部"成立。

## 4. 核心机制：归类权决定维护负担，而归类权无程序

**机制链：** Rust binding 必须依附某个 C 子系统的 API →"binding 属于谁"决定谁承担长期维护、谁在 API 变更时被绑住 → 该归类无成文程序，由 Torvalds 个案裁决 → 被判归属方无程序性救济，只能公开抗辩或退出 → 抗辩的表达强度（"癌性肿瘤"）与救济渠道的缺失成正比。

**鉴别预测：** 若该机制成立，冲突应集中出现在**被动接受 binding 的核心子系统**（DMA 型），而非主动引入 Rust 的驱动子系统（DRM、NVMe）。材料与之相符：DRM 维护者主动加速（M4），冲突却发生在 DMA。

**替代解释 A（技术负担说）：** 冲突源于双语言维护成本。**削弱证据：** Hellwig 的核心反驳指向文档效力与 Linus 的私下立场（M1），是程序性而非成本性论证；Greg KH 亦称 Rust/C 交互问题少于预期（M4）。未被排除，但解释力弱于机制说。

**替代解释 B（代际更替说）：** 材料**不足以区分**——快照只包含一名反对者的表态，无法判断 Hellwig 代表一类立场还是个体立场。这是本次分析最重要的证据缺口。

**失效条件：** 若出现一份进入内核树、经广泛评审的成文 Rust 政策，且归类争议按该文本裁决，本机制降级。

**为何尚未失败：** 三个缓冲仍在工作——驱动层作为默认入口把多数 Rust 代码挡在核心子系统之外；"既有 C 代码不重写"消除了存量维护者的生存威胁；数十年共存的时间尺度把冲突摊薄到任何一年都不致命。**任何加速采纳的干预都会同时削弱这三个缓冲。**

## 5. 关键风险节点与条件情景

**节点：** DRM 若在约一年内要求新驱动必须用 Rust（M4），"子系统自治"将首次被用于**强制**而非豁免的方向。政策文档写的是"可因带宽原因不采用"，未写"可要求必须采用"——同一原则的两个方向，规则地位尚未被检验。

**情景 A（延续，无干预）：** 归类争议逐案裁决，反对者转为静默。可观察特征是公开冲突频次下降而非上升。M6 记录 2026 年未见新一轮公开冲突——这**既可能**是关系缓和，**也可能**正是本情景的表现，快照不足以区分。

**情景 B（成文化）：** 政策进入内核树并获广泛同意，D1 与 D7 同步改善。触发条件是一次代价够高的归类争议。

两者非穷尽、非互斥，**不构成概率分布**。
