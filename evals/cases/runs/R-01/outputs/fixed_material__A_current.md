# Rust-for-Linux 与内核维护者：定性已结束，归属规则仍未成文

**系统类型：** relational（分析对象是两个社群的互动格局本身）｜**as_of：** 2026-09-09

## 摘要：结束的是"留不留"，没结束的是"算谁的"

2025 年底东京 Maintainers Summit 认定 Rust 实验结束（M3），解决了 Rust 是否留下，但没解决 2025 年真正引爆冲突的问题：**一段 Rust binding 到底属于谁**。Hellwig 认为 DMA 被迫接受 Rust，Torvalds 与 R4L 认为 binding 只是 DMA 的又一个使用者、不属于 DMA 子系统（M2）。同一事实两种归类，而归类决定维护负担落在谁头上。这个分歧至今没有成文裁决规则，只有个案仲裁。

七维评分（关系系统语义：衡量可管理性与稳定性，不是友好程度）：
D1 边界与规则 **3 →**｜D2 克制的收益结构 **3 →**｜D3 信号保真 **2 ↑**｜D4 演化与棘轮 **4 →**｜D5 共存叙事 **4 ↑**｜D6 纠缠结构 **2 ↓**｜D7 权力与否决 **3 →**

三条核心判断：病灶在 D6×D3 而不在 D5——共存叙事是健康的，跨语言耦合与沟通渠道是薄的；Torvalds 设计了一条罕见的好机制，把"不参与"从免费否决变成有价格的退出；2026 年**看不到**新一轮公开冲突，但材料无法区分"已被制度吸收"与"转入沉默"。

## 〇、这个系统的行为体不是"两个阵营"，而是四类角色

把它读成"Rust 派 vs C 派"会看错结构。材料里可辨认的是四类角色：**推动方**（Ojeda 与 R4L，无正式权力，唯一资源是说服力与 Torvalds 的背书）；**仲裁者**（Torvalds，唯一能改元规则的人）；**采纳型维护者**（Greg KH、Airlie——他们不是中立方，而是把 Rust 转化为自己子系统政策的转译层，Airlie 甚至比 R4L 更激进）；**承担型维护者**（Hellwig 一类，位于被 binding 穿过的底层子系统，不写 Rust 却要承受耦合）。

真正的分界线不是语言偏好，是**位置**：叶子子系统（驱动）采用 Rust 是净收益，非叶子子系统（DMA 这类被广泛依赖的底层）是净负担。Hellwig 的反对是这个位置的理性表达，不是保守主义。规则层级同样分三层：正式规则（树内文档、patch review）、非正式规则（子系统自治惯例、Torvalds 的公开表态）、元规则（Torvalds 一个人）。2025 年的冲突恰好发生在一份文档试图跨层——用非正式载体承载正式权责分配。

## 一、规则是口头的，正式效力一直被质疑（D1=3 →）

Hellwig 的第一反应不是反对内容，而是反对**形式**：一个网页没有用，要生效必须进内核树并获得广泛同意（M1）。这不是程序洁癖。内核社群的合法规则载体是版本控制下的树内文档，网页不受 patch review 约束、可单方修改。R4L 用一份树外文档规定树内的权责分配，等于在这个社群的规则体系之外立法——即便内容正确也天然缺乏效力。他同时指出文档有事实错误，进一步削弱其权威。

红线本身也不清晰。官方页反复强调子系统自治（M4），但自治的边界正是争议对象：Airlie 说 DRM 约再有一年将只接受 Rust 新驱动（M4），这是自治权的合法行使，却在实感上生产出"被强迫"——强制落到驱动作者而非维护者身上，"没有维护者被强迫"字面仍成立、语义已被掏空。清晰的字面，模糊的适用范围。实验结束消除了一个歧义源，归属规则的空白原地未动。

## 二、Torvalds 的规则是这个系统最好的一件设计（D2=3 →）

"没有维护者被强迫使用 Rust，但选择不参与就同时放弃对影响其子系统的 binding 如何开发的影响力"（M2）——机制价值被低估了。开源社群的典型病理是免费否决：既不参与也不放行，成本外部化给推动方。Torvalds 把退出定价了：可以退出，代价是失去话语权。否决点因此转成自选退出，是教科书级的激励相容设计。

但它只在一个前提下成立：不参与的维护者**真的**不承担成本。Hellwig 的 binding creep 论证（M1）正是攻击这个前提——最终每个非叶子子系统都会被波及，C 侧改动必须开始考虑 Rust 侧。若成立，规则退化为"承担负担且放弃影响力"，激励从相容滑向倒置。材料没有任何量化证据判定 creep 的实际速率（无 patch 量、无跨语言 breakage 统计），这是本次最关键的空白。Greg KH 称 Rust/C 交互问题少于预期（M4），但那是印象而非数据。

## 三、最脆弱的是信号，不是叙事（D3=2 ↑）

系统里存在一条被点名的公私信道不一致：Hellwig 称"没有子系统被强迫"的说法"被 Linus 证明是错的"，并指 Linus 在公开场合躲在"实验"这个说法后面、私下另作决定（M1）。无论指控是否准确，它本身就是 D3 的诊断结果——**关系中的一方已经不相信公开表述反映真实立场**。在一个把公开邮件列表当作唯一权威记录的社群里，这是重症状。加上文档载体的非正式性，推动方与怀疑方之间没有一条双方都承认的可靠信道。

高带宽同步只有一年一次的 Maintainers Summit，而 2026 年的峰会结果查无记录（M6）。趋势记 ↑ 的唯一理由是：定性结束关闭了"这东西会不会被撤掉"这个持续噪音源。

## 四、没有升级棘轮，时间尺度是数十年（D4=4 →，D5=4 ↑）

关系系统最危险的模式是每轮交手抬高基线；这里相反。争议以一次性定性收尾而非反复交手，方向是降级的。Torvalds 明确 Rust 是增补而非替代、既有 C 不重写，乐观估计 2030 年 Rust 仍不到内核代码 5%，现实是数十年共存（M3）。Ojeda 在胜利时刻主动告诫仍有大量工作、并非所有配置架构工具链可用（M3）——赢家自陈局限，是共存叙事健康的强信号。

D5 扣分只来自 Hellwig 的"癌性肿瘤"比喻（M1）：材料里唯一一句否定对方存在权的修辞。但它是个体立场而非阵营立场，被 Torvalds、Greg KH、Airlie 三个高权重节点的反向表态包围。

## 五、结构病灶：跨语言耦合把模块化边界变成硬耦合（D6=2 ↓）

binding creep 不是修辞，是耦合拓扑的必然结果。一个 Rust 驱动要用 DMA，就必须在两者之间架一层，这层代码同时约束两侧。内核的模块化假设是子系统可独立演进；跨语言 binding 破坏的正是这一点。而且它单调上升：驱动是既定入口，Apple silicon、Google 的 Android 驱动、Nova、NVMe、已进主线的 GPIO 抽象（M4）——每多一个 Rust 使用者，就多一组穿过 C 子系统边界的约束。

关键在 D6 与 D3 的乘积。耦合在上升，裁决耦合归属的信道很薄，意味着 DMA 式冲突会在下一个子系统原样重演，每次都靠个案仲裁。**恶性回路**：耦合上升 → 归属争议 → 无成文规则 → 诉诸私下裁决 → 公私信道不一致加剧 → 下次争议更难在公开渠道解决。

与之并存的还有一条**良性回路**，它是这个系统目前不崩的原因：D5（共存叙事）→ D2（克制有收益）→ D4（无棘轮）→ 回到 D5。因为"数十年共存、既有 C 不重写"被反复公开确认，双方从克制中得到的收益高于从升级中得到的收益，于是没有一轮交手抬高基线，而没有棘轮又反过来让共存叙事保持可信。这条回路的脆点是它整段依赖 Torvalds 的公开表态——D7 的个人化仲裁既是良性回路的支点，也是它的单点故障。

其余较强的跨维传导：D1→D3（规则无正式载体，争议只能走私下渠道）、D3→D7（信道不畅时每次争议都被迫上升到仲裁者，强化个人化）、D6→D2（耦合上升侵蚀"不参与就无成本"的前提）。四条边构成的图里，**D3 参与的回路最多**，但可直接干预的是 D1——写下规则是唯一一个操作者周一早上就能动手的动作。

## 六、权力清晰，但依赖一个人（D7=3 →）

结构清楚：Torvalds 持终极仲裁权，子系统维护者持局部否决权，R4L 无正式权力、靠说服与背书运作。极性不对称，但不对称本身不构成不稳定——R4L 已拿到永久性定性，没有掀桌动机。

扣分有二：仲裁高度个人化，M2 的框架分歧最终由 Torvalds 的一次归类决定而非由规则决定；以及**继任问题材料完全没有覆盖**。这条关系的稳定性在多大程度上绑定在一个人身上，本次无法判断——标记 UNKNOWN。

## 七、三种解释都还活着，这本身是结论

2026 年没有找到该关系新一轮公开冲突的报道（M6）。三种互斥解释：

- **H1 制度吸收**：定性结束后争议转入技术执行，无事可争。
- **H2 沉默退出**：反对者停止公开发声，转为 exit（不再 review Rust patch、静默交接）而非 voice。沉默在开源社群往往是退出的形态，不是同意。
- **H3 观测缺口**：M6 是否定性发现，"没找到"不等于"没发生"。

材料无法区分三者：区分 H1 与 H2 所需的证据（review 活跃度、维护者变更、邮件列表语调）一条都没有。**默认按 H3 处理**，任何"关系已趋稳"的判断都属未验证。M5 中关于 Linux 7.0、Rust NVMe 进稳定树、Debian/Android/Ubuntu 下游动向的说法均来自二手博客且被明确标注警告，本分析不采信、不作为任何评分依据。

## 八、三年演化：最可能的结局是"稳定但反复摩擦"

- **制度化收敛（约 45%）**：归属规则以某种形式成文（哪怕只是若干子系统的局部惯例固化），冲突转为技术执行。D1/D3 上行，D6 的负担被显式分配。前置信号是树内出现 Rust 权责文档。
- **摩擦性共存（约 40%，最可能的单一路径）**：没有成文规则，冲突随每个新 binding 逐个复发，每次靠个案仲裁压下去。系统不崩，但 D3 长期停在 2 分区，承担型维护者持续沉默流失。这是"不做任何事"的默认结局。
- **分叉压力（约 15%）**：DRM 式强制在多个子系统同时到位，叠加一次高冲突的归属裁决，把摩擦推成公开的阵营对立。材料里没有任何 2026 年的升级信号支持这一支，概率主要来自 D6 的单调恶化，而非已观察到的事件。

结构上最接近的历史类比是**长周期技术共存中的转译层争夺**，而不是任何一种敌对格局：双方都不想让关系结束，争的是成本分摊。这类关系很少崩溃，但也很少自愈——它们停在摩擦态，直到有人把分摊规则写下来。

## 九、风险节点、杠杆点与可证伪预测

**节点 1（12 个月内）：DRM 强制令与"没人被强迫"叙事的正面碰撞。** Airlie 的时间表到期时，首次出现由合法自治权产生的事实强制。触发条件是 DRM 把要求写进成文文档；级联路径是其他子系统援引先例，一次性引爆 D1 的模糊适用范围。

**节点 2（持续）：归属规则空白。** 每个新增 Rust 使用者都是一次 DMA 式争议的抽奖。杠杆点也在这里——**把 binding 归属从个案仲裁变成树内成文规则**，同时修复 D1（规则有正式载体）、D3（争议有公开信道）、D6（耦合责任预先分配）。这恰好是 Hellwig 2025 年提出的形式要求，采纳它同时是对最强反对者的实质让步，成本低而回报跨三个维度。副作用：成文规则会削弱 Torvalds 的裁量空间（D7 略降），且规则本身的起草会重新打开 2025 年的争论。

**节点 3：UNKNOWN。** Torvalds 仲裁角色的继任安排，材料无覆盖。

另外两条可执行处方，都针对同一条恶性回路：（a）**把 binding 的维护责任显式绑定到 Rust 侧**——每个跨子系统 binding 指定 Rust 侧责任人，C 侧维护者的义务止于不主动破坏接口。这直接拆掉 Hellwig 前提中的"承担负担且无影响力"，代价是 R4L 侧人力吃紧，且需要 binding 数量增长时同步扩员。（b）**把 Airlie 式的子系统强制统一为公示制**——要求任何"只接受 Rust 新代码"的决定提前一个发布周期在树内公示。这不阻止强制，只让强制可预期，把节点 1 的一次性碰撞摊成缓坡。两条处方与主杠杆不冲突，但都会增加 R4L 的流程负担；若三条同时推，R4L 的带宽本身会成为新瓶颈——这正是那份引发争议的政策文档最初想说的事。

可证伪预测（自 2026-09-09 起）：

1. 到 2027-06-30，至少出现一次新的公开 binding 归属争议，结构与 DMA 案同构（一方称被迫接受、另一方称 binding 只是使用者）。信心 0.6。证伪：期间无此类公开争论。
2. 到 2027-12-31，binding 归属仍无进入内核树、经 patch review 的成文规则。信心 0.7。证伪：出现该文档。
3. 到 2026-12-31，DRM 尚未正式实施"新驱动只收 Rust"的成文要求（Airlie 的一年表述会滑期）。信心 0.55。证伪：DRM 文档明确该要求。
4. 到 2027-12-31，无主要 C 子系统维护者以 Rust 为由公开辞任或交接。信心 0.25（低信心刻意保留：若 H2 成立，此条应被证伪）。

**监控指标：** ①树内是否出现 Rust 政策/归属文档（D1+D3 的直接读数）；②DMA、NVMe、GPIO 等已有 binding 的子系统，其 C 侧维护者是否仍在 review Rust patch（区分 H1/H2 的唯一可观测量）；③下一次 Maintainers Summit 的 Rust 议题是执行细节还是权责争议——若回到权责，说明 2025 年的定性没有吸收冲突。

**方法论声明：** 依据截至 2026-09-09 的公开材料。二手来源已排除。无量化数据（贡献者数、patch 量、review 延迟），故评分为结构性判断而非测量；继任安排、2026 年峰会、2026 年冲突状况三项标记 UNKNOWN。
