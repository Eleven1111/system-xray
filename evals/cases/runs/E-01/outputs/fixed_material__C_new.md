# Rust Foundation 系统诊断：治理已经修好，钱的结构还没有

**as_of 2026-09-08 · system_type: government_agency · 完整性：partial（缺财务口径与基础设施成本量级）**

## 1. 最重要的判断：压力不在治理层，在成本与收入的错配

治理侧没有可见病灶——2026 年的材料显示的是结构按设计运转，而非危机。真正未解的是一条财务结构问题：**crates.io 的成本随使用量增长，收入却按会员档位收取，两者之间没有连接**。2025-12 董事会记录的"CloudFront 请求消耗 AWS 捐赠额度快于预期"是这条错配的第一个可观测信号；到 2026-03 董事会，应对仍停留在"员工提出的早期想法"。

但必须同时说清：**现有材料不足以区分"结构性剪刀差"与"一次性流量异常"**。两种解释都能解释已知的全部事实。判断哪一个成立，只需要一个基金会已经拥有、但未在检索范围内公开的数字：crates.io 的年度出口/请求成本与剩余捐赠额度。建议动作因此不是干预，而是取这个数（见 §6）。

**适用边界**：本文只覆盖公开治理与财务披露；未覆盖 crates.io 技术架构、缓存命中率、镜像生态，以及分档会费收入拆分。

## 2. 边界：两个系统，一份预算

分析对象是 Rust Foundation（法人、资金与基础设施），**不是** Rust Project 的技术治理。二者由 RFC 3392 明确切开：Leadership Council 与九个顶级团队管语言与工程，基金会管钱、法务、商标与基础设施，Project Directors 是二者的接口。评价目标取"Rust 生态的长期可用性"，而非任何单一会员的利益。

**边界敏感性**：若把 AWS 从"捐赠方"重新纳入为"系统内的基础设施子系统"，D6 的耦合结论会显著变化——把捐赠额度当外部馈赠，风险是断供；把它当内部产能，风险是定价权。本文按前者处理，并在 §4 标出这一依赖。

## 3. 已知与未知

**已知（M1–M5）**：2025 年募得 $5.1M，$2.7M 直接投入项目与社区，含 $2.0M 全职维护成本；会员五档，Platinum 附董事会专属席位，Associate 免费；Arm 于 2025-09-03 升级 Platinum，且此举发生在"部分组织收缩开源投入"的背景下；Council 每公司最多两人、代表软上限三届、轮换按期执行（2026-03 已完成，2026-09-23/25 为下一轮）；crates.io 已加装分析埋点以识别流量异常；Maintainers Fund 按 RFC #3931 先行 MiR 项目，费率按月固定而非按小时。

**对当前判断有实质影响的未知**：① crates.io 服务成本的绝对量级与剩余额度的时间窗（**决定性**）；② 分档会费收入拆分与集中度；③ 捐赠方代表担任 Treasurer 时是否有回避规则；④ 2025-12 提到的流量异常是否已被定位与处置。前三项都在基金会 publications 页的完整年报或章程文件中可能存在，本次未取得。

## 4. 核心机制

**机制 A：使用量驱动成本 × 会员制收入 —— 结构性剪刀差（依赖关键假设）**
链条：生态增长 → crates.io 请求量上升 → CloudFront 出口成本线性上升 → 消耗定额捐赠额度 → 额度是缓冲而非收入，耗尽后成本落回现金预算。而收入侧由会费与赞助构成，与下载量无任何联动；消费者（CI、构建机、下游企业）不承担边际成本，是典型的公地结构。支持：M4 的额度超预期消耗、基金会主动签署 Joint Statement on Sustainable Stewardship 并把可持续资助列入议程。
**替代解释**：一次性的异常/滥用流量，靠缓存策略与限流即可回到正常曲线——这也完全解释了"加装埋点"这个动作（埋点是排查异常的工具，不是重构收入的工具）。
**鉴别预测**：若为结构性，2026 年内应看到一份**带成本口径的提案**进入董事会议程（而非仅"早期想法"）；若为异常流量，应看到流量治理措施的技术公告，且额度消耗曲线恢复而无资金机制变化。
**失效条件**：任一公开记录显示额度消耗在缓解措施后回到预算内。
**敏感性**：结论完全依赖 2025-12 的单条董事会记录；移除它，剪刀差只剩理论推演。判定为**依赖关键假设**，不是稳健结论。

**机制 B：新增的钱和吃紧的钱不是同一笔（结论较稳健）**
2025 年可见的资金增量都流向**人**：$2.0M 全职维护、Maintainers Fund/MiR、OpenSSF 出资的 security advisories tab、Arm 升档带来的会费。基础设施的**带宽**这一项，唯一的实质来源仍是单一捐赠额度。与此同时 2026-03 同一次会议还在扩张运营范围：批准认证项目、通过 Symposium 加入 RIL、受理 AI 研究倡议动议。范围扩张会占用同一批治理与运营带宽，而未解的那条线没有对应的资金承诺。这不是浪费的指控——认证项目本身可能带来收入——而是指出：**优先级排序发生在一个成本量级未知的前提下**。

**为何尚未失败（正向分析）**：三个缓冲仍在工作——捐赠额度本身、Arm 在逆风期升档所体现的会员意愿、以及 Council 那套防 burnout 规则（软上限三届、moderator 可随时退出）保住了人力侧不再出现 2021 年式集体辞职。修任何一处之前，先别破坏这三者。

## 5. 七维评分与近期可裁定预测

D1 边界 **4 →**（法人与项目治理切割清晰，接近 NHS 型的清晰授权带轻微模糊）｜D2 激励 **3 →**（Platinum 付费换席位是透明的付费代表制，且被 Project Directors 等额投票权约束；缺陷是无人的激励与 crates.io 成本收敛挂钩）｜D3 信息 **3 ↑**（"快于预期"本身说明成本遥测滞后于事实，但埋点已补，回路在改善）｜D4 演化 **3 →**（$2.7M/$5.1M 投回项目属净负熵输入；基础设施议题延迟决策构成温和的未来透支）｜D5 合法性 **4 ↑**（逆风期的 Platinum 升档是一次外部信号；危机叙事属 2021–2023，不属 2026）｜D6 耦合 **2–3 ↓?**（单一供应商的实物捐赠承担核心公共品，且该捐赠方代表任 Treasurer；给区间而非单值，因为"是否存在替代 CDN 安排"未知，这一项决定它是 2 还是 3）｜D7 权力 **4 →**（两类董事等额投票、四个 officer 职位在会员方与项目方之间 2–2 分布、Council 每公司上限两人且轮换按期发生）。

**竞争假设**：H3"董事会被范围扩张分散、赞助方主导议程"被 M5 的否定性发现**压制但未排除**——检索无冲突报道，不等于无冲突；证据层级仅为 T2/T3 的缺席。H1（结构性）与 H2（异常流量）**当前证据无法区分**，不应择一报告。

**预测**（均可证伪）：
1. `occurrence`，2026-12-31 前，基金会公开渠道出现一条**具体的** crates.io 可持续性措施（命名的资金机制、供应商变更或流量政策），而非再一次"讨论早期想法"——0.7。
2. `persistence`，至 2027-06-30，crates.io 对下载方保持免费、无计量收费——0.8。破坏条件：任何面向发布者或消费者的用量计费公告。
3. `occurrence`，2027-03-31 前，公开宣布第二家基础设施/CDN 提供方参与 crates.io 分发——0.3。材料中没有任何供应商多元化的迹象，故给低值。
4. `occurrence`，2026-12-31 前，认证项目产出至少一份公开的机构认证框架或首批认证方名单——0.6。这条用于检验范围扩张是实质还是 renewal theater。
5. `persistence`，2026-09-25 新一轮 Council 代表按公告日程就位——0.85。防 burnout 规则是否仍在执行的最便宜探针。

## 6. 跨维交互：一个良性回路，一个待观察的耦合

只记录有传导机制的配对，不做 21 对铺陈。

**D5 × D3 × D1（良性、当前在运行）**：合法性存量高 → 会员愿意在行业逆风期升档（Arm 案）→ 现金收入支撑 $2.0M 全职维护 → 维护质量维持生态信任 → 回到合法性。这条回路是系统当前最大的资产，也是它最容易被误伤的地方：任何降低使用便利性的成本措施（限流、计费、注册门槛）都从 D5 一侧扣款。这解释了为什么"直接收费"不是一个便宜的解法——它动的是回路的输入端。

**D6 × D2（待观察，方向未定）**：单一供应商承担核心公共品，同时该供应商在董事会持有 Treasurer 职位。这个结构在**良性运行时**是优势——捐赠方在场，预算可预期；在**压力下**才显出问题——决定"是否寻找替代供应商"的桌子上，坐着现任供应商的财务负责人，而材料没有说明是否存在回避规则。这不是对任何人的指控：材料里没有任何滥用迹象，且 officer 席位在会员方与项目方之间 2–2 分布构成对冲。它是一条**需要被观察的结构**，判定为"证据不足以区分"。

**关键风险节点（唯一一条）**：*承担 crates.io 出口成本的那一笔实物捐赠额度，其剩余窗口未被公开量化*。级联路径：额度耗尽 → 成本落入现金预算 → 与 $2.7M 项目投入争夺同一笔钱 → 削减维护或紧急引入用量限制 → 触碰上面那条良性回路的输入端。触发条件：捐赠续期谈判、单次流量事件、或某个白金会员减档。**时间窗口无法估计**——这正是 §3 中第①项未知的直接后果，也是本诊断最该被补上的一个数。

## 7. 行动卡（按外部观察者权限撰写；无干预权）

**A1 · 取一个数，而不是做一个判断。** 从基金会 publications 页的 2025 完整年报中提取 crates.io/基础设施成本行与捐赠额度披露。这是唯一能区分机制 A 与其替代解释的低成本步骤。完成定义：拿到金额与口径年度；取不到即记录"未披露"，本身也是 D3 的一条观察。触发升级：若成本已占非项目支出的显著份额，机制 A 从"依赖关键假设"升为主要判断。

**A2 · 把 2026 年底设为复核点。** 观察指标：董事会纪要中该议题的成熟度是否从"早期想法"进入带成本口径的提案。所有者：读者自己。阈值**待校准**——材料未给出基线消耗速率，任何红黄绿灯都会是编造的。

**A3 · 依赖 crates.io 的组织：现在保留缓冲，不要现在重建。** 最小下一步是确认自身具备 vendor/镜像能力（应对任何限流或可用性变化），成本以小时计。护栏：在 A1 的数字出来之前不要投入建设私有注册中心——那是用一个未量化的风险交换一份确定的长期维护负担。

**明确不建议的事**：以当前证据推动"crates.io 应当收费"或"应当立即更换供应商"。两者都超出证据能支撑的范围，且可能破坏 §4 中正在起作用的缓冲。

## 8. 审计附录

**覆盖审计**：目标与评价主体 `covered`｜规则与元规则 `covered`（RFC 3392、会员档位、officer 结构）｜权力与合法性 `covered`｜信息与测量 `covered`（埋点、成本遥测滞后）｜依赖与替代 `unknown`（**最重要的缺口**：替代 CDN、镜像生态、切换成本）｜资源与存量 `partial`（有总额与去向，无分档拆分、无基础设施成本行）｜分配与外部性 `partial`（免费消费者与付费会员之间的成本转移已识别，未量化）｜生产与服务过程 `not_applicable`（非本次决策焦点）。

**方法与限度**：因果能力级别 **L1**（解释性机制图，仅给条件性方向推演）。未做参数化模型与效果估计——没有时间序列、没有对照组、没有成本单位，入口条件不满足。七维分数为序数标签，不可作为干预量级的依据；D6 以区间给出，因为它跨假设不稳定。历史类比未启用：本案与库内案例的相似度会由一个覆盖不全的分数向量驱动，价值低于直接指出那条缺失的成本数据。

**证据基础**：全部结论源自单一快照材料（rustfoundation.org 官方页面、Inside Rust Project Director Update 各期、董事会纪要摘述、Arm 会员公告、The Register、The New Stack）。多条转述指向同一原始公告的，按同一来源家族计一份权重。M5 是一条**否定性发现**——"未检索到 2026 年治理冲突报道"约束了危机类假说，但不构成其不存在的证明。
