# Rust Foundation：治理结构与 crates.io 可持续性分析

**信息截止：2026-09-08。** 以下判断仅基于该时点可见的公开材料，未覆盖之处逐项标注。

## 一、两个身体，一个耦合点

这个系统由两套独立演化的治理机器组成，各自防的是不同的病。

**Foundation 侧**管钱、法律实体与会员关系：董事会分 Member Directors（会员机构代表）与 Project Directors（Rust Project 代表），**两类投票权相等**；董事会定方向并聘任、监督 Executive Director，ED 负责日常运营。

**Project 侧**管技术：Leadership Council 由 RFC 3392 于 2023-06-20 确立，取代 Core Team。它的设计动因不是权力分配而是**结构性 burnout**——旧 Core Team 既要识别与排序团队职权外的工作、又要亲自做（JT Turner: "no way we can wear this many hats and do this many things."）。新结构的核心动作是**只识别与排序，主要靠委派**；日常执行留在九个顶级团队。

两者的唯一强耦合点是董事会里的投票权对等。这一条承担了极大的结构负荷：它是"出钱方不能单方面决定技术方向"这个承诺的**全部**制度实现。材料未显示 Foundation 层面另有防俘获条款（例如同一法律实体能否持有多个 Member 席位、Project Director 与 Member Director 的席位数是否硬性锁定）——这是一处需要年报才能填的空。

## 二、钱如何兑换成治理权

会员分五档，**Platinum 附带董事会专属席位**——出资到顶档就直接换来一个投票席，这是明码标价的兑换。另一端 Associate 面向非营利与教育机构、**免费**、不贡献收入：它买的是生态正当性与人才管道，不是现金。

值得注意的是官职的落点。主席 Nell Shamrell-Harrington 同时是 Microsoft（白金）的 Member Director、本职为 Microsoft Principal Software Engineer；Treasurer 由 AWS 代表 Seth Markle 出任。副主席与秘书则分别由 Project Director Ryan Levick、David Wood 担任。也就是说，**四个官职在两侧各占其二，但主席与财务两个最实质的位置都落在最大的两家出资方身上**。这不构成失当——在一个会费驱动的基金会里这几乎是默认结果——但它意味着投票权对等并没有延伸到议程设置权与财务口径的对等。材料未提及回避（recusal）规则，无从判断这一点是否已被制度处理。

## 三、真正的压力点在成本侧，不在政治侧

系统当前最尖锐的问题不是谁掌权，而是一条基础设施的单位经济。

crates.io 经 CloudFront 的请求**消耗 AWS 捐赠额度快于预期**（2025-12 董事会）。这句话里藏着三层结构性麻烦：

1. **成功即成本。** crates.io 的负载随生态繁荣单调上升，而收入端（会费）与负载完全脱钩。生态越成功，缺口越大——这是一条正反馈，不是可以熬过去的波动。
2. **需求侧外生。** 拉取流量由 CI、镜像、自动化工具等基金会无法直接管控的行为决定。crates.io 增加分析埋点以识别流量异常，正是承认"我们目前还不知道钱花在谁身上"。
3. **供给侧集中。** 承担这项成本的是单一会员的实物捐赠，而该会员的代表恰好是基金会的 Treasurer。这不是利益冲突指控，而是一个耦合度提示：**基础设施续命、最大出资方、财务口径三者落在同一条线上**，任何一端松动都会同时影响另外两端。

再看响应速度。2025-12 问题上桌；2025 下半年基金会签署 Joint Statement on Sustainable Stewardship（对应 2025-09 OpenSSF 声明），开启社区讨论；2026-01 crates.io 侧交付了埋点；2026-03-10 董事会讨论员工提出的运营可持续化**"早期想法"**。到本次信息截止（2026-09-08），材料中**没有出现任何已定型的资金机制**。

诊断时钟走得比决策时钟快得多：九个月里，测量、发声、议程化都做了，**定价、限流、分层服务、专项基金这类会改变现金流方向的动作一个都没落地**。这是本案最值得盯的一条。合理的解释至少有两个——一是有意慢，先拿到流量归因数据再谈机制，避免拍脑袋定价；二是这类决定天然需要跨会员共识，而共识成本高。材料不足以区分。

同一次 2026-03-10 会议还批准了**面向培训机构的认证项目（优先于个人培训课程）**。这是材料中唯一一个形态上像新收入的东西，且刻意选了 B2B、低人力密度的路径——与一个不能承担运营开销扩张的组织的约束相符。但它同时把收入基础进一步压在机构客户上，而 Arm 升级白金时被特意点出的背景正是"部分组织正在收缩开源投入"。**两条主要收入路径指向同一个宏观风险敞口。**

## 四、两种失败模式通过预算耦合

Project 侧防的是人力枯竭，Foundation 侧面对的是现金枯竭。这两套机器各自对自己的病很在行，但它们在一处相连。

Council 的解法是**不亲自做、只委派**，配上防 burnout 的软上限三届轮换、以及 moderator 可随时退出（此条可追溯到 2021-11 moderation team 集体辞职）。这个设计有效，但有一个必然后果：**新增负载不能再靠核心层加班吸收**，只能落到顶级团队或落到付费产能上。于是 burnout 防线把劳动问题转译成了资金问题——而资金侧正是当前吃紧的一侧。

Maintainers Fund 的成型印证了这条转译链：由 Leadership Council 设立的 funding team 管理，依 RFC #3931 先做 Maintainer in Residence，费率参考调查数据与 Zig 等基金会做法，**定为按月固定而非按小时**。按月固定是一个刻意的制度选择——它避免把志愿者关系改造成计时监督关系，保护的正是 Council 一直在保护的东西。但它也意味着这是一笔**刚性、可预测、只会往上走的经常性支出**，与 crates.io 的成本曲线同向。

从财务比例看空间有限：2025 年募得 $5.1M，其中 $2.7M 直接投入 Project 与社区（含 $2.0M 用于全职维护的总成本/工具/开支），其余约 $2.4M 覆盖治理、安全、财务与运营。**接近一半的钱花在维持组织本身**，这一档在基金会里不算异常，但也说明"从行政里挤出钱补基础设施"的腾挪余量不大。分档收入拆分在搜索结果中缺失，收入集中度因此无法量化——这是评估脆弱性的关键缺口。

## 五、一处被投票权对等掩盖的不对称

材料指出 Project Director **承担法律责任与部分法律责任风险**，且须为 Rust Project 在册成员。Member Director 一般是大公司雇员，身后有雇主的法务与保险资源；Project Director 则以个人身份承接同等票权与不对等风险。**票数对等、风险不对等。**

这不是一个当下事件，而是一个供给侧约束：它会缩小愿意且有能力担任 Project Director 的人群，长期看可能让这些席位偏向已有雇主背书的社区成员——从而悄悄削弱席位对等原本要保障的独立性。材料未说明是否存在 D&O 保险或补偿条款，无法判断该风险是否已被覆盖。

## 六、否定性发现及其边界

针对"2026 年治理危机/公开冲突"的检索**没有找到**相应报道；2026 年可见的是结构在按设计常规运转——代表轮换按期执行（2026-03-20 确认、3-27 起参会；下一轮 2026-09-23 确认、9-25 起参会），防 burnout 规则实际生效。

这条否定性发现应当被认真采纳：它排除了"当前处于治理危机"这一类假说，把"危机"叙事正确地归还给 2021–2023 那一段。轮换按公布日程发生，是治理机器真的在转的**正面**证据，而不只是坏消息的缺席。

但它的证明力有边界：检索缺席只对**已公开升级的冲突**是强证据，对内部摩擦、代表招募困难、团队产能不足这类不会见报的问题几乎没有约束力。因此正确的读法是：**这个系统的当前风险是代谢性的，不是政治性的**——而代谢性风险的特征恰恰是安静地累积，直到某个额度用尽的时刻才变成事件。

## 七、值得盯的先行指标

按可证伪程度排序，未来若干个月内以下事项的发生与否，比任何叙事都更能定位这个系统的走向：

1. **2026-09-23 那一轮 Council 轮换是否照常完成**——这是防 burnout 设计仍在工作的最低成本检验。
2. **是否出现 crates.io 的成型资金/流量机制**（分层、限流、赞助带宽、专项基金中的任意一种）。若又一个季度只有"早期想法"，则应把它读作共识成本过高，而非信息不足。
3. **埋点数据是否公开成流量归因**。公开意味着基金会准备用数据去做需要外部说服力的决定（如向重度使用方收费）；不公开则倾向于内部消化。
4. **认证项目是否产生可披露的收入**，以及 MiR 是否从试点扩为常规。
5. **任何白金会员的降档或退出**，尤其是与 Arm 升级时被点名的"部分组织收缩开源投入"背景相互印证的情况。

## 材料缺口（不以背景知识补齐）

- 会员分档收入拆分与集中度 → 完整年报在基金会 publications 页，本次未取得。
- Foundation 董事会是否有等价于 Council "同一法律实体最多两人" 的防俘获条款。
- 官职任职者的回避规则；Project Director 的责任保险或补偿安排。
- crates.io 具体成本量级与 AWS 额度余量；流量构成。
- funding team（Project 侧）与 Foundation 预算之间的资金来源与协调关系。
