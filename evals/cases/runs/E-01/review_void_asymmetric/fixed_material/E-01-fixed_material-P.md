## 1. 决策摘要

**最重要的判断：** 治理侧没有正在发生的危机，可观察到的是一套按设计常规运转的结构；真正需要盯住的是一条**外部观察者目前无法定量的依赖**——crates.io 的分发成本由 AWS 的实物捐赠额度吸收，该额度"消耗快于预期"（2025-12 董事会），而成本可见性（分析埋点）是在问题暴露之后才补上的。这条依赖同时是基础设施依赖、资助依赖与治理关系（AWS 既是创始白金会员，其代表 Seth Markle 又当选 Treasurer），三者叠在同一个来源上。

**建议动作及执行者：** 执行者只能是读者自己。① 建立三项低成本监测（成本定量披露是否出现、Council 反俘获条款是否被修订、9 月轮换是否按期完成）；② 优先补一条决定性事实——基金会储备金与运营月数（公开年报可查），它是本报告中唯一一个能翻转维度分档的未知；③ 在自身系统一侧保留 crates 镜像/vendoring 的切换选项，但**不因本次诊断触发迁移**——当前证据不支持"中断风险已上升"这一结论。

**主要不确定性与适用边界：** 全部结论建立在一份二手编纂快照上，其中绝大多数原始出处是被诊断对象自己发布的（rustfoundation.org、Inside Rust、RFC 3392）；独立第三方来源只有两条（The New Stack、The Register）。没有任何一条断言的链接被本轮实际打开核验，全部登记为 `reachability: unchecked` / `status: unresolved`。M5 的否定性发现（未找到 2026 治理危机报道）只覆盖英文公开报道、且来自 4 次检索，它能约束"当前处于治理危机"这类假说，但不能证明不存在未被报道的紧张。

**是否存在影响当前决策的 `needs_review` 对象：** 有。`C-09`（AWS 额度消耗快于预期）是本报告载荷最大的单条断言，只有一个来源家族支撑，且是本轮唯一直接驱动风险判断的证据；依赖它的机制 `MECH-1`、预测 `P-1`、行动 `A-1` 全部标 `needs_review`。它不阻断行动 A-1/A-2（二者本身就是补证与监测），但阻断任何"crates.io 面临近期中断风险"的强判断。

## 2. 系统边界与目标：分析对象是"基金会 + Rust Project 治理 + crates.io 运营"三者的合成体，结论对这个边界敏感

**纳入：** Rust Foundation（董事会、Executive Director、会籍体系、预算）、Rust Project 治理侧（Leadership Council、九个顶级团队、moderation team、funding team）、crates.io 的运营与成本结构。

**排除：** Rust 语言与编译器的技术演进本身；下游使用者（依赖 crates.io 的企业与个人）的成本与风险；AWS 作为公司的内部动机与其云业务战略。

**评价目标是谁的目标：** 本报告用的是**外部依赖者**的评价标准——"这套结构能否持续、可预期地提供 crates 分发与语言维护"。这不等于基金会自身的目标（其章程目标包含支持维护者、生态健康、安全等），也不等于会员企业的目标（影响力与供应链保障）。同一套事实按不同评价主体会得出不同的"健康"。

**边界敏感性检查（`boundary_sensitivity`）——两处结论明确依赖边界：**

1. **纳入 / 排除 Rust Project 治理侧。** 若只看基金会法人实体，权力图景是"付费会员分档 + Platinum 附带董事会专属席位"，读起来像影响力可购买的结构；把 Project Directors 纳入后，材料显示两类董事**投票权相等**（M1），权力图景实质改变。**[DIM] 的判断对这条边界高度敏感，报告采用"纳入"口径**，排除口径下 [DIM] 应显著更低。
2. **把 AWS 当外部环境还是系统内部。** 作为外部环境时，额度问题是"供应商/赞助方风险"；纳入系统内部后（它同时是创始白金会员、Treasurer 席位所有者、基础设施提供者），同一事实变成**治理内部的角色叠加问题**——评估"是否该减少对单一云的依赖"的桌子上，坐着这家云厂商的代表担任财务主管。本报告采用"纳入"口径，因为排除口径会让 [DIM] 的最关键特征不可见。这不是对任何个人行为的指控：材料没有任何证据显示该席位影响过相关决策，这是**结构观察，不是行为断言**。

**关于 `system_type` 轨道：** `scoring-calibration.md` 没有"非营利基金会/开源基金会"轨道。本报告使用 `platform` 轨道（其锚点覆盖 Linux/开源、GitHub、AWS 依赖等最接近的对象）。按打分纪律第 6 条，本报告的分数**不与其他轨道的同数值分数等价**；`score_basis_version = platform-track/2026-09`。

## 4. 核心机制与替代解释

深入两条机制，加一条较短的补偿性机制。不做[FRAMEWORK]等长铺陈。

### 4.1 MECH-1：分发成本被实物额度吸收，因此不进入现金预算的反馈回路，直到额度接近耗尽才成为议题

**解释目标：** 为什么一个年度募资 $5.1M、治理程序完备的组织，会在 2025-12 才把 crates.io 的分发成本作为需要"找短期与长期办法"的问题提上董事会，并在此后才增加分析埋点。时间窗口 2025-11 至 2026-03；比较基准是"成本若以现金支付时的常规预算审查节奏"。

**机制链：** AWS 以捐赠额度形式承担 crates.io 经 CloudFront 的出口成本（行为体：AWS、基金会、crates.io team；规则：实物捐赠而非现金采购）→ 该成本不产生逐月的现金支出信号，也就不进入基金会常规预算科目的审查回路（中介过程：会计与预算流程中的可见性缺口）→ 用量增长在很长时间内不触发任何管理响应（延迟）→ 直到额度余量出现"快于预期"的耗尽迹象，问题才以离散事件形式进入董事会议程 → 事后补建观测能力（增加分析埋点识别流量异常）与"早期想法"层面的方案讨论。

**可观察变量：**

| 变量 | 定义 / 代理指标 | 获取方式 | 缺失情况 |
|---|---|---|---|
| 额度余量 | 剩余捐赠额度占年度承诺比 | 仅基金会内部可见 | 完全缺失 |
| 成本可见性建立时间 | 分析埋点上线时点 | crates.io 开发更新（C-10，2026-01-21） | 有月份，无精确上线日 |
| 问题进入议程时间 | 董事会首次讨论该议题 | 2025-12 董事会（C-09） | 有月份 |
| 现金化程度 | 预算中 crates.io 基础设施自付科目 | 年报 / 预算摘要 | 缺失 |

**支持：** C-09（额度消耗快于预期，且基金会仍在"找办法"而非已有方案）、C-10（埋点是与"控制带宽驱动的成本"直接相关的新增能力）、C-14（到 2026-03 仍处于员工提出的"早期想法"阶段）。三条同属来源家族 F2，**折叠后是一族，不是三条独立支持**。

**反对 / 削弱：** C-11 显示基金会有实质预算与年报流程（存在常规财务审查）；C-14 同次会议同时批准了认证项目并推迟 AI 倡议，说明议程管理有取舍能力而非被动救火。

**替代解释 A（增长解释）：** 不存在可见性缺口。额度消耗加快是生态用量真实超预期增长的结果，基金会的观测正常，埋点增加是常规运维改进而非事后补救。
**替代解释 B（口径解释）：** "快于预期"只是预算编制时的预期设定问题（保守/乐观差异），不反映任何治理或可见性缺陷；这是任何按年编预算的组织都会出现的偏差。

**鉴别预测（若 MECH-1 成立，相比 A、B 应额外看到）：**
- 后续公开材料出现的是**成本可见性改造**（按流量/成本的定量披露、限流或缓存策略调整、镜像/CDN 多元化），而不只是"追加赞助"；
- 2026 或 2027 年预算中出现 crates.io 基础设施的**自付现金科目**；
- 讨论中出现"我们此前不知道成本结构"性质的表述。
若 **A** 成立，应看到下载量/请求量增长数据被明确引用为主因，解决方案偏向扩容与追加赞助，且成本口径始终不进入现金预算。
若 **B** 成立，应看到问题在 2026 年预算批准后即消失于议程（同次会议已批准 2026 年预算，C-09），不再出现"可持续性"条目——但材料显示到 2026-03 该议题仍在推进（C-14），这对 B 构成弱反证。

**失效条件：** 若披露显示基金会此前已有逐月的 crates.io 成本追踪、且额度消耗落在事前预测区间内，MECH-1 降级为"预期偏差"，本报告的 [DIM]/[DIM] 判断须同步下调风险权重。

**行动影响：** 决定读者把"额度耗尽"当作**突发风险**（可见性缺口下，外部先看到的是服务变化而非预警）还是**渐进可见风险**（成本内部化后会有公开的财务痕迹）。这直接决定 §6 监测指标选哪一个，以及是否需要保留镜像切换的提前量。

**敏感性扰动结果：**
- 移除载荷最大的证据 C-09 → 机制无立足点，结论不成立。
- 合并同源转载（C-09/C-10/C-14 折叠为 F2 一族）→ 支撑从"三条"降为"一族"，机制**排序不变但强度显著下降**。
- 切换有争议的编码：把 C-10 对"事后补救"的支持从 direct 改为 inferred（材料只给月份先后，没给因果表述）→ 时间顺序论证退化为推断。
- **判定：`依赖关键假设`；其中"埋点在成本问题暴露之后才补"这一时序论证判定为 `证据不足以区分`**——月份先后不能排除埋点本就在常规路线图上。

### 4.2 MECH-2：burnout 被当作存量来管理——把"识别排序"与"执行"分离，并给退出留了合法出口

**解释目标：** 为什么 2021–2023 期间反复出现的治理断裂（2021-11 moderation team 集体辞职、Core Team 不可扩展），在 2026 年的材料里表现为按期轮换的常规运转（C-16）。窗口 2023-06 至 2026-09；比较基准是改制前的 Core Team 结构。

**机制链：** 旧结构要求同一批人既识别与排序团队职权外的工作、又亲自执行（C-06，JT Turner 的"no way we can wear this many hats"）→ 志愿者时间与注意力这一存量被持续超额支取，耗竭率高于补充率 → 到达阈值时以集体退出形式释放（2021-11 moderation 辞职）→ RFC 3392 改变的是**规则层而非参数层**：Council 只识别与排序、主要靠委派（九个顶级团队各派代表），加软上限三届鼓励轮换、同一实体最多两人、moderator 可随时退出并由团队补位（C-05、C-07）→ 单个岗位的支取率下降、退出不再需要以危机形式表达 → 轮换按公告日期发生（C-08）。

**可观察变量：** 每轮候选人数与竞争度（缺失）；连任比例与是否触及软上限（缺失）；席位空缺时长（缺失）；轮换是否按公告日期完成（C-08 给出两轮的计划日期，2026-03 那轮的完成情况材料未确认）；moderation 补位是否实际发生过（缺失）。

**支持：** C-05、C-06、C-07、C-08（同属 F3+F2，折叠后为两族）。
**反对 / 削弱：** C-16 是**缺席证据**——"没找到危机报道"来自 4 次英文检索，其排除力受采集广度限制；上表五个变量中四个缺失，意味着本机制的结果侧几乎没有直接观测。

**替代解释：** 轮换按期发生只证明**流程在跑**，不证明 burnout 存量改善。同一现象可以由"参与人数下降、席位无人竞争因而轮换毫无摩擦地完成"产生——那是耗竭的另一种表现，而非缓解。这是典型的过程指标冒充结果指标。

**鉴别预测（若 MECH-2 成立，应额外看到）：** 候选人数/竞争度维持或上升；连任比例低于软上限、有真实的新面孔进入；moderation 团队出现过实际补位并公开记录。若替代解释成立，应看到席位空缺、确认日期延期、同一批人连续占位至软上限、以及新的集体退出事件。**这两组观察在当前材料中都不存在**——机制与其替代解释目前无法区分。

**失效条件：** 出现任一团队代表席位长期空缺、轮换公告延期、或再次发生团队级集体辞职。

**行动影响：** 决定读者能否把治理风险从"结构性风险"降级为"常规运行"。当前答案是：**可以降级 2021–2023 那一段的危机叙事（C-16 的排除力足以支持这一点），但不能升级为"burnout 已被解决"的正面结论**。

**敏感性扰动结果：** 移除 C-16（缺席证据）→ 对"当前无危机"的支持消失，但机制链本身不受影响；改用另一个评价主体（把"维护者个人的可持续性"而非"治理连续性"作为评价目标）→ 全部结果侧变量缺失，**"改善"不再成立**。**判定：`证据不足以区分`**——制度设计的存在有据（结构性事实，来源可靠），实施效果无据。

### 4.3 MECH-3（简）：付费席位与平权投票互相抵消，是当前治理未被资金结构俘获的直接原因

Platinum 会籍附带董事会专属席位（C-12），这是一条把资金转换为治理入口的正式通道；同时 Member Directors 与 Project Directors 投票权相等（C-01），Council 层面又设"同一公司或法律实体最多两人"（C-07）。两者构成明确的对冲：资金买得到席位，买不到多数。**替代解释**：正式平权不等于实际影响力平等——议程设置、信息优势与非正式影响力不在投票权表里，材料对此完全没有覆盖（`unknown`）。**鉴别预测**：若对冲实质有效，应能观察到至少一次 Project Directors 与 Member Directors 立场分歧被公开记录；若只是形式平权，公开记录中不会出现分歧，一切议题以一致同意通过。

### 4.4 "为何尚未失败"的正向分析，以及一条修复前必须先看的警告

维持当前状态的补偿机制，按可观察性排序：① **AWS 的实物额度本身**——它正是那个吸收了成本、让 crates.io 至今无需现金化的缓冲；② 募资规模与会籍的边际增长（Arm 在别处收缩开源投入时逆势升级为 Platinum，C-13）；③ 治理层的平权投票与 Council 反俘获条款；④ 执行层的分布式冗余（九个顶级团队承担日常职责，Council 主要委派）；⑤ moderation 的随时退出与补位条款，把个人耗竭从系统性事件降级为可吸收的人员变动。

**修复前的警告：** 对 MECH-1 最直觉的"修复"是减少对单一云厂商的依赖。但依赖与缓冲在此处是**同一个东西**——现在正在吸收 crates.io 成本的，就是这条依赖。任何以"降低集中度"为目标的动作，若不同步建立现金化的成本承担能力，会先摧毁缓冲、再暴露成本。这条对读者不构成行动（读者无权限），但它决定了读者应当如何**解读**未来看到的动作：一条"多云化/镜像化"公告若不伴随预算科目变化，风险是上升而非下降。

### 4.5 因果能力分层：本次停在 L1，L2 与 L3 的入口条件均不满足

- **L2 拒绝理由：** 存量—流量模型需要单位、初值、延迟与**参数区间**。额度余量、月度出口成本、增长率全部缺失（§3.4），没有 `parameter_ranges` 就出结论等于把任意假设包装成结果。
- **L3 拒绝理由：** 没有定义好的估计目标，也没有可辩护的识别策略——不存在对照组（只有一个基金会、一次改制），RFC 3392 的改制是全局同时生效的，双重差分的数据形状不存在。
- 因此本报告只给**条件性方向推演**（"若机制成立，压力增大时应额外看到 X"），不给任何效果幅度。§5 的情景不带概率，§6 的阈值多数标"待校准"。

### 5.3 条件情景（两条，**不构成概率分布**，不给概率）

不使用"热寂/剧变/涌现"三分法——那是讨论隐喻，对一个运转中的基础设施组织没有解释力。情景由本系统的主要外部冲击（云成本、赞助环境）与已识别机制构造。

**情景 S-A「成本内部化」：** 基金会把 crates.io 的分发成本部分转为现金预算科目，或引入 CDN 赞助多元化、缓存与限流策略，并伴随定量披露。
*先行观察信号：* 年报出现基础设施自付支出科目；crates.io 侧公布带宽治理或镜像策略；董事会摘要从"早期想法"推进到"已批准方案"。
*对读者的含义：* 风险从不可见转为可见，中断风险下降，长期成本压力上升（可能传导为会费结构或服务分层的变化）。

**情景 S-B「额度续期覆盖」：** AWS 追加或续期额度，问题被再次推迟，成本口径不变。
*先行观察信号：* 出现追加捐赠公告；后续董事会摘要中 crates.io sustainability 条目消失；无任何定量披露。
*对读者的含义：* 表面稳定，但 MECH-1 的可见性缺口未被修复，[DIM] 的集中度进一步固化——**这是"看起来更安全、实际更依赖"的情景**，需要在监测中与 S-A 明确区分，不能都记作"问题解决了"。

**为什么不给概率：** 没有基础率（此类基金会额度续期的历史频率未知）、没有额度合同条款、没有预算数据，也没有可援引的专家范围。按规范，`probability_basis` 缺失即不出数字。两条情景**不互斥也不穷尽**（可能先 B 后 A），因此更不能合成 100% 的分布。

**稳健行动判断：** 在 S-A 与 S-B 下都值得做的，只有"监测 + 补一条决定性事实 + 保留自身侧的切换选项"；任何在当前证据下触发迁移的动作在两个情景中都不占优。
