## 结论：仪器跑通了，并暴露出三个缺陷

### ✅ 跑通的部分

- 三条路径记录、预算记账、可比性硬校验、盲评打包、映射表分离，全链路可用。
- 预算实测可比：`searches 1.0× / tool_calls 1.2× / wall_clock 1.5× / tokens 1.43×`，
  均在 1.5× 容忍度内。
- 路径 C 的结构化底稿通过统一契约校验，且**校验在真实内容上抓到了真实弱点**（见下）。

### 🔴 缺陷 1：盲评标签与路径名同字母（已修）

标签用 `A/B/C`，路径名恰好也是 `A_current/B_generic/C_new`。
试点这次随机打乱后 **label-C 真的落在了 C_new 上**——评审若假设"标签 A = 路径 A"，
有 1/6 概率白捡一次正确身份。改为与路径名无字母交集的 `P/Q/R`。

### 🔴 缺陷 2：篇幅差 3.28×（已加校验）

三条输出 1420 / 2886 / 4658 字符，最长的是新版。方案 §14.4 明确说"报告更长"不得作为成功指标，
但盲评拿到三份长短悬殊的材料，长的天然显得更用心。
现在 `check_comparability` 会报 `output_length` 比值并在超 2× 时警告——
**不阻断**（篇幅差异可能就是方法差异的真实结果），但要求评分说明里写明不得以长度作为增量依据。

### 🔴 缺陷 3：同会话运行 = 路径间上下文污染（未修，需用户决定）

三条路径由**同一模型在同一会话内先后产出**。写完新版协议的分析再去写"普通分析"，
后者不可能真的回到无知状态——这是评估设计上的硬伤，会**系统性高估**新版的增量。

修法只有一个：三条路径在**隔离上下文**中分别运行（独立会话，或 subagent）。
本轮没做，因为派 subagent 需要用户明确要求。**正式评估必须先解决这一条**，
否则 12 案跑完得到的数字不可用。

## 契约校验在真实内容上的表现

对路径 C 的结构化底稿跑 `--validate`，抓到的都是真问题，没有一条是噪音：

| 告警 | 是不是真问题 |
|---|---|
| 三条载荷性断言各只有 **1 个独立来源家族** | 是。且三条全部来自**被分析对象自己**（基金会官网、自家董事会纪要） |
| C2（operational_status）已 273 天 > 7 天阈值 | 是。引用的是 2025-12 董事会纪要，拿它描述"当前"成本状态确实过期 |
| C1（financial_period）已 251 天 > 120 天阈值 | 是。2025 年报数据，跨了两个季度 |
| C4（charter_rule）已 1176 天 > 730 天阈值 | 是。RFC 3392 是 2023 年的，期间可能已被修订而未核查 |
| C5 无时间锚点 | 是。否定性检索结果本来就没有事件时间 |
| 三个要素组 unknown 且影响当前决策 | 是。额度剩余量、CDN 替代成本、外部性归属，全都没数据 |
| 完整性推导为 `partial` | 是。未跑 ACH、未做信源核验 |

**按断言类型的时效在这里明显优于统一阈值**：同一份分析里，
一条 273 天的运营状态断言被点名，而 1176 天的章程条款用的是完全不同的阈值。
若沿用旧的"六个月"统一阈值，C2 会漏报（273 天内但语义上早已过期的运营状态），
C4 会误报（章程本就该按年计）。

## 对正式评估的三条要求（试点得出）

1. **三条路径必须隔离上下文运行。** 同会话产出的对照不可用。
2. **评分说明里必须写明不得以长度作为增量依据**，并把 `output_length` 比值随材料一起交给评审组织者
   （不给评审本人看，那会引入新的暗示）。
3. **固定材料轮的检索是共享的**，`searches` 计数对三条路径相同——
   这一项在固定材料轮天然可比，真正需要盯的是 `tokens` 与 `wall_clock`。
