## 两条必须写进结果解释的限制

**1. 工具链的贡献没有被分离。** 九条里只有 **E-01 的 A_current** 真的调用了
`agent/` 下的 Python 工具（ACH 打分、causal_graph、danger_zones）。
E-01 的 C、P-01 的 C、R-01 的 C **都自行决定不调**，各自给了理由
（单一快照不满足输入条件 / 任务只要一份 Markdown）。

所以本轮固定材料轮测的是**协议对推理的约束**，不是工具链。
"C 更好"不得读作"工具有用"，"C 不够好"也不得读作"工具没用"——**工具基本没被执行**。
要测工具，得另设一轮把调用工具写成硬要求，那又会引入新的不对称（只有 A/C 有工具可调）。

**2. 同一模型。** subagent 与主会话是同一模型，只隔离上下文不隔离模型先验。
协议 §14.1 本就要求同一模型，符合设计；但报告里不得说成"独立复现"。

## 去标识的负控

盲评目录对 `system-xray|七维|机制卡|行动卡|ACH|路径名|SKILL.md` 的扫描：**0 命中**。
同一条扫描打在未去标识的原始产出上：每份 1–3 命中。
**负控会响**，所以"0 命中"是去标识做了事，不是扫描恒真。

## 第一轮（作废）：九份产出因提示词不对称废弃

作废原因不是任何一次运行失败，是**我给三条路径写了不同的指令**：

| 我给谁 | 写了什么 |
|---|---|
| B_generic | "长度控制在 1500 字以内" |
| A_current / C_new | 没有任何长度约束，另各附一份该规范的要点清单 |

输出字符数 B 2,787 / C 23,472 / A 28,486——**差 10.2×**。这不是方法差异，是指令不对称，
它同时污染盲评（体量本身是强暗示）与因果解释（B"说得少"可能只因为我不让它多说）。

产出移入各案 `outputs_void_asymmetric/`，盲评包移入 `review_void_asymmetric/`，
**未删除**——它们现在是"不对称提示词能造成多大差异"的实测记录。

### 一处更正

第一版本文件写着 P-01 的 A/C、R-01 的 A "因 429 中断**未产出**"，并说"没有输出就不记录"。
**那是错的。** 核对磁盘，这三份产出文件完整存在（结尾完整，非截断）。
中断发生在 agent 交回运行数据那一步，不是写文件那一步。
准确说法是"**有输出，但没有预算记录**"——运行失败和记录失败不是一回事。

### 第一轮逼出的两处仪器修复

**缺陷 4：把"授予的资源"和"消耗"混成一个可比性数字。**
旧逻辑下 E-01 会被整轮判为不可比（tokens 2.47× > 1.5×），等于说
"新方法只要更费就不能被评估"——把成本问题误当成效度问题。
反过来直接放宽阈值，又会掩盖一个**真实**的效度威胁：算力差异本身可能就是输出差异的原因。
现在两者都说：`comparable`（硬）阻断送评；`cost` + `warnings`（软）不阻断，
但强制成为任何"某条更好"结论的限定条件。

**预算上限口径错了。** 预登记时把 `tokens` 上限设为 40,000、`tool_calls` 设为 6，
实测用了 5.8–14.4 万 tokens，全部"超标"。那不是超支，是上限设错——
对消耗类设上限本就没有意义。现在 `budget_cap` 只对授予类资源生效。
原上限保留在各案 manifest 里未删。

## 第二轮发现的一个新坑

**subagent 自报的字符数不可信。** R-01 的两条各自报"7991 字符，已核对"——
那是 `wc -m` 在本机 locale 下输出的**字节数**，实际字符数是 3,556 和 3,445。
两条独立运行的 agent 报出同一个数，正因为它们犯的是同一个错。

落位脚本用 Python `len()` 独立复核，所以没被带偏。但如果信了自报，
"共同上限"就形同虚设——它们会以为自己贴着上限，实际只用了 44%。
**校验必须由组织者做，不能由被测方自报。**
